# 数据集：列、值、改列、快照

## 起名

- 数据集名、列名：小写字母开头，只含小写字母、数字、下划线，最多 48 个字符（`orders`、`unit_price`）。
- `title`、列的 `label` 是给人看的显示名，最多 64 个字符，可以是中文。

## 列的类型和值怎么写

| 类型 | 值的写法 | 例 | 常见的错 |
|---|---|---|---|
| `text` | 文本，最多 1 万个字符 | `"东区"` | 给了数字（要写成 `"12"`） |
| `integer` | 整数（数字，不是文本） | `42` | `"42"`、`4.2` |
| `decimal` | 数字 | `1200.5` | `"1200.5"`、`NaN` |
| `date` | `YYYY-MM-DD`，必须是日历上存在的一天 | `"2026-01-31"` | `"2026-02-30"`、`"2026/1/31"` |
| `datetime` | 带时区的 ISO 写法 | `"2026-01-31T08:00:00+08:00"`、`"…Z"` | 没带时区、用空格分隔 |
| `boolean` | `true` / `false` | `true` | `1`、`"true"` |

- 空就写 `null`，或者干脆不给这一列。必填列不能空。
- **必填**：列定义里写 `"required": true`（`{ "name": "region", "type": "text", "required": true }`）。不写就是可空。
- 多出来的列（数据集里没有的列名）会被拒。先 `dataset_define` 加列，再写。
- 时间存下来统一成 UTC（`2026-01-31T00:00:00.000Z`），读回来是这个写法。

## 取值说明（业务口径）

一列的取值各是什么意思，写在列定义的 `values` 里：「取值: 意思」，最多 100 项，意思最多 64 个字符。`dataset_list` 原样给出，看数的人、接手的席位靠它知道「异常」对应哪个值。

```json dataset
{ "name": "inspections", "title": "巡检记录", "key": ["id"],
  "columns": [
    { "name": "id", "type": "integer", "label": "编号", "auto": true },
    { "name": "day", "type": "date", "label": "日期", "required": true },
    { "name": "device_id", "type": "integer", "label": "设备编号" },
    { "name": "result", "type": "text", "label": "结果", "values": { "ok": "正常", "bad": "异常" } }
  ] }
```

- 谁写：定义数据集的人（建台的席位或管理层）。口径是业务定的：派任务的人说了「异常就是 bad」，就照写进来；没人说过的不要自己编。
- 写在哪：只写在数据集的列上，这是口径唯一的来源。视图组件的 `value_labels` 管的是页面上显示成什么字、什么颜色，可以和取值说明一致，但不能代替它。


- `key` 是一个或几个列名。主键列自动是必填的；不能是小数或布尔。
- **主键由服务端分配**：唯一的整数主键列可以写 `"auto": true`。追加（`dataset_append`、表单提交）时行里不给这一列，服务端按现有最大值往上数，应答的 `ids` 是分配到的号；给了的照用，分配时跳过同一批里给了的号。写入是一个接一个排队做的，两个席位同时追加也不会撞号。**不要自己查最大值再加一**。整份替换和按主键更新还是要给主键。
- 带幂等键重放时 `duplicate` 为 `true`、`inserted` 为 `0`，`ids` 是第一次分配的号。
- 有主键才能用 `dataset_upsert` 和 `dataset_delete_rows`。
- 一批数据里主键重复、或者 `append` 时和已有的行撞了，整批拒收。

## 数据集怎么设计

- **能用外键查到的列别冗余存。** 巡检记录里有 `device_id`，设备的名字、所在区域就留在设备表里，别在每条巡检记录里再存一份：存了两份，写的时候没人核对两边是不是一致，迟早会写进互相矛盾的行。要按区域统计，就在写入的时候算好放进一个数据集（查询不能连表），或者让巡检记录只存区域、不存设备名——总之同一件事只存一处。
- 一种东西一个数据集（设备一个、巡检记录一个），不要把不同的东西塞进同一个数据集再用一列区分。

## 改列（再调一次 `dataset_define`，给完整的新定义）

| 想做的事 | 行不行 |
|---|---|
| 加一列 | 行。已有数据时只能加成可空的；写完数据再改必填 |
| 改显示名、改标题 | 行 |
| 把一列改成必填 | 行，前提是现有的行这一列都不空 |
| 改主键 | 行，前提是现有数据按新主键不重复 |
| 删一列 | 行。会先自动留一份快照 |
| 改一列的类型 | **不行**。新建一列，把数据重写进去，再删旧列 |

列定义每改一次是一个新版本，留最近 100 版。

例：给 `orders` 加一列可空的备注（给的是完整的新定义，原来的列一个不少）。

```json dataset
{ "name": "orders", "title": "订单", "key": ["id"],
  "columns": [
    { "name": "id", "type": "integer", "label": "单号" },
    { "name": "day", "type": "date", "label": "日期", "required": true },
    { "name": "region", "type": "text", "label": "区" },
    { "name": "status", "type": "text", "label": "状态" },
    { "name": "amount", "type": "decimal", "label": "金额" },
    { "name": "memo", "type": "text", "label": "备注" }
  ] }
```

## 快照与退回

- 自动留快照的时候：整份替换之前（上一代）、按主键删到了行之前、删列之前、退回之前。也可以手工留。
- 每个数据集最多留 5 份，旧的先清。**最近一次整份替换留下的上一代不会被清**，直到下一次整份替换——替换之后又删了多少次行，替换前的数据都退得回去。
- 内容和最近一份一样的不再存（不改变数据的操作不占名额）。
- 退回之前会把当时的数据也留一份，退错了能再退回来。快照里有、现在已经删掉的列会被丢掉，结果里写明。

| 工具 | 做什么 | 要给的 |
|---|---|---|
| `dataset_snapshots` | 列出一个数据集现有的快照：编号、为什么留的（整份替换 / 删行之前 / 删列之前 / 退回之前 / 手工）、多少行、谁、什么时候 | `bench`、`dataset` |
| `dataset_snapshot` | 手工留一份 | `bench`、`dataset`、`note` |
| `dataset_restore` | 退回到某一份 | `bench`、`snapshot_id`（从 `dataset_snapshots` 拿）、`note` |

每次写入的结果里也带着这次自动留的快照编号（`snapshot_id`），记下来最省事。
- `append` 和 `upsert` 不自动留快照。要保险，写之前手工留一份。

## 读

- `dataset_list`：这个台有哪些数据集、列定义、行数、占多少字节、上次谁在什么时候改的。不含快照，快照用 `dataset_snapshots` 看。
- `dataset_query`：按查询描述读，见 `query.md`。
