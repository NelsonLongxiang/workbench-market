# 上限和时限

超了都是整批拒收，报错里写明是哪一项。

| 项 | 上限 |
|---|---|
| 一个台的数据集 | 50 个 |
| 一个数据集的列 | 60 列（主键最多 8 列） |
| 一个数据集的行 | 5 万行 |
| 一个数据集的数据量 | 32 MB |
| 一个台的在用数据合计 | 256 MB |
| 一次 `append` / `upsert` / `delete_rows` | 5000 行、16 MB |
| 一次 `replace` | 到数据集的上限（5 万行、32 MB） |
| 一格文本 | 1 万个字符 |
| 一次查询取回 | 5000 行、各格字符数合计 800 万 |
| 一个视图取回的内容合计 | 800 万字符（超出的那个组件显示出错） |
| 视图描述 | 200 KB、20 个视图、每个视图 40 个组件 |
| 每个数据集的快照 | 5 份 |
| 历史版本 | 视图 100 版、列定义 100 版 |
| 幂等键有效 | 这个台最近 5000 次写入之内 |
| 一句说明（note） | 200 个字符 |

数据量按 UTF-8 字节算：文本按字节数（一个汉字 3 字节），数字和布尔算 8，空算 1。

| 时限 | 多久 |
|---|---|
| 读 | 3 秒 |
| 写 | 15 秒 |

时限从轮到它开始算，排队的时间不算。排着队等的读写超过 200 件时，新来的当场回「正忙」。

## 超了怎么办

- **行数或数据量到顶**：这种台不适合放明细全量。先在写入方聚合好（按天、按区汇总），只把汇总放进来；明细留在原来的系统里。
- **一次写入太大**：分批 `upsert` / `append`，每批不超过 5000 行、16 MB，每批一个幂等键。
- **查询取回太多**：`select` 少取几列，`limit` 调小，或者改成聚合。
- **读超时**：筛选范围缩小；长文本列上的去重计数、最大最小值最慢，能不用就不用。
