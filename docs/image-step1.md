# 图片 · 第 1 步实施规格

状态：实施规格，待评审；评审过了按本规格分三个 PR 实现。依据：设计稿 [docs/image-support-design.md](image-support-design.md)（#1002、#1003）和属主 2026-11-23 在 UI/UX 席会话里的四句话（见第一节）。代码基线：release/10 `752b0a21`。

## 一、属主已定（不再讨论）

| # | 属主原话 | 落到本规格 |
|---|---|---|
| D1 | 「图片只支持链接吧，但是，不经由浏览器访问，由工作台市场统一处理，我会准备一个本地的图库提供本地访问地址」 | 只存链接，不收上传、不存原图；浏览器只请求市场的代取地址，由市场去取图 |
| D2 | 「无需凭据，就是静态资源链接」 | 市场访问图库不带凭据 |
| D3 | 「还有一些图片链接是公网的」 | 链接可以是图库地址，也可以是公网地址 |
| D4 | 「这块的资源不需要考虑。那么多安全措施。不影响」 | 图片按非敏感资源处理：不设域名白名单，不做按引用判权、去元数据、重新编码、冻结留副本这些措施。设计稿第 3 节 W 表里的成套挡法不在第 1 步实现 |

设计稿第 4 节里还挂着的取舍，按 D4「从简」取最简单的一项（第六节列出），评审时有异议在 PR 上提。

## 二、这一步做什么、不做什么

做：

- 数据视图：数据集加一种列类型 `image`，格子里存一个图片链接；`table` 和 `records` 两个块把它显示成缩略图，点开看原图。
- 报告：模板第 2 版加 `image` 节点，图片链接来自模板参数、字段或数据行；冻结的报告只记链接。
- 代取：一条服务端路由，按「这个人能看这个台」放行，然后由市场去取图交给浏览器。

不做：上传；表单（form 块）填图；图片编辑；报告导出 PDF（现在本来就没有 PDF 服务）；冻结时留副本或记哈希；按台隔离图库目录。

## 三、链接和配置

- 新环境变量 `WM_IMAGE_GALLERY_BASE`（可选）：图库的地址前缀，例如 `http://127.0.0.1:8090/`。按仓库红线写进 README。
  - 配了：格子里可以写图库内的**相对路径**（不以 `http://`、`https://` 开头的），代取时拼在这个前缀后面。图库搬家只改配置，不改数据。
  - 没配：只收完整的 `http(s)://` 链接，相对路径写入时报错。
- 格子的值：文本，最长 2048 个字符；只认两种写法——`http://` 或 `https://` 开头的完整链接，或（配了前缀时）不含 `..` 段、不以 `/` 开头的相对路径。其余写入时报 400「图片须为 http(s) 链接或图库内的相对路径」。
- 浏览器拿到的永远是市场自己的地址：`/api/bench-views/<台>/image?u=<格子里的原值，URL 编码>`。

## 四、代取路由

`GET /api/bench-views/:bench/image?u=…`。**不新增动作**：路由声明为 `bench-store.render`（读档），处理里照报告跨台列表的写法自己判（见第 1 条），这样动作清单、预设、角色矩阵都不用改。

1. **判权**：照单台路由的 `allowActor` 认人（跨站 403、管理口令 403、匿名 401），然后 `may(actor, 'bench-store.render', 台) || may(actor, 'bench-store.report-read', 台)` 任一为真就放行，都不是回 403。**先判权，再去取图**：没权限的请求不发起任何外部请求。
2. **还原地址**：`u` 是相对路径就拼 `WM_IMAGE_GALLERY_BASE`；是完整链接就照用；都不是回 400。
3. **取图**：`fetch`，只发 GET，不带读者的任何请求头（Cookie、Authorization、Referer、X-Forwarded-*），`redirect: 'manual'`，3xx 当失败；单张上限 5 MB（按流读，超了就断）；10 秒超时；同时进行的代取最多 8 个，超了回 503。`WM_OUTBOUND=off` 时不发起，回 503「图片暂不可用」。
4. **回给浏览器**：上游的 `Content-Type` 是 `image/png`、`image/jpeg`、`image/webp`、`image/gif` 之一就原样转出，否则回 415（为了不让市场同源上被打开的「图片」变成网页）。响应头：`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、`Cache-Control: private, max-age=300`、`Referrer-Policy: no-referrer`。
5. **缓存**：进程内按完整地址缓存 5 分钟、合计不超过 64 MB；命中缓存前照样先判权（第 1 条）。
6. **唯一保留的一条防护**：完整链接解析出来的地址是本机回环、私网（10/8、172.16/12、192.168/16）、链路本地（169.254/16，含云元数据）、`::1`、`fc00::/7`、`fe80::/10` 时拒绝（回 400），**图库前缀那台主机除外**。理由：这条保护的是市场自己和内网里的其它服务（控制面、凭据库），不是图片；不做的话，任何能看台的人都能借这条路由读本机的管理接口。实现成本是一处检查。属主要是连这条也不要，评审时提出来就删。

## 七、用例（先红后绿）

1. 写 `image` 列：完整链接、配了前缀时的相对路径都能写；`ftp://`、`javascript:`、含 `..` 的相对路径、没配前缀时的相对路径、超长都报 400。
2. 代取判权：匿名 401；管理口令 403；跨站 403；台上没有授予的人 403 且**图库没收到请求**；只有 `render` 的人、只有 `report-read` 的人都能取到。
3. 代取结果：图库返回 PNG → 200 且字节一致；返回 `text/html` → 415；返回 302 → 502；超过 5 MB → 502；超时 → 504；`WM_OUTBOUND=off` → 503。
4. 防护那一条：`http://127.0.0.1:<控制面端口>/…`、`http://169.254.169.254/` → 400；图库前缀那台回环主机 → 放行。
5. 不转发：图库收到的请求里没有读者的 Cookie、Authorization、Referer。
6. 缓存：第二次取不再请求图库；没权限的人在缓存命中时仍是 403。
7. 视图：`image` 列拿来筛选、排序、聚合报错。
8. 报告：`image` 节点引用参数、字段、数据行都能冻结出链接；引用的列不是 `image` 类型时编译报错；报告页显示走代取路由。
9. 页面：表格和记录卡里图片列出缩略图；取不到显示占位；单测核源码里没有内联样式和写死的颜色。

测试用合成数据和一个测试脚本自己在本机回环上起的假图库，不碰外网。
