# 租户边界评审件 v1（workbench-market multi-tenant）

> 评审席产出 · 派单 direct-76fb2438（总工席）· 材料：24 业务台现态（web×9 + market-app×15）+ 9877 隔离范本 + 本席 39 个隔离实例留痕（五次 PR 复算历史）
> 定位：多租户形态下的**边界断言 + 隔离证据 + 风险表**——为 tenant_review 提供评审基线

## 一、租户模型现状

市场当前无显式租户概念——「租户」以三种形态隐式存在：
| 形态 | 承载 | 边界机制 |
|---|---|---|
| **工作台行**（24 台） | 每行=一个登记单元 | 行级字段隔离（url/auth_config/cookie_set_id）|
| **自产台 slug**（15 个 market-app） | 每 slug=一个应用租户 | slug 键控：app_data/app_files/版本目录 per-slug |
| **MCP 会话**（网关激活后） | mcp/<name>=调用面租户 | 会话授权+调用审计 per-identity |

## 二、边界断言集（可机械验证）

### B1 工作台行级
- B1.1 /go/:id 命名空间：台 A 的门户路径不可触达台 B 的资源（路径前缀硬隔离）
- B1.2 auth_config 注入边界：凭据只注入所属台的代理请求（goAuth 前置中间件按行取值）
- B1.3 cookie_set 挂接：cookie 池按 cookie_set_id 绑定，跨台不泄漏（域匹配过滤在注入层）

### B2 自产台 slug 面
- B2.1 app_data/app_files 键控：POST /api/apps/:slug/data 仅写本 slug 行（slug FK 校验 404 先拒）
- B2.2 版本目录物理隔离：DATA_DIR/apps/<slug>/v<N>/ 每 slug 独立目录树
- B2.3 删台级联：卸载清盘+清元数据不跨 slug（PR#38 时代 404 不落盘语义）

### B3 MCP 面
- B3.1 会话边界：tools/list 按会话授权过滤（网关 P1 语义）
- B3.2 审计粒度：mcp_calls 按 identity 记录（未授权与不存在同应答——存在性不泄露 A10 同源）
- B3.3 上游聚合隔离：taste__* 上游与本地工具命名空间分离

### B4 共享数据面（最薄处）
- B4.1 SQLite 单库：全租户共库——行级隔离靠 WHERE 键控（slug/id），**无库级隔离**
- B4.2 Redis 热态：sop_runs 热数据键控 run_id——无租户维度键
- B4.3 endpoint-stats：键空间=端点路径（非租户维度）——按台聚合依赖 /go/:id 归一

## 三、隔离证据（9877 范本链）

| 证据 | 出处 |
|---|---|
| E2E_PORT 隔离实例全链（25 组打 9877/9878/9879/9887/9888/9889） | PR#43/#55 A/B 定因 |
| 隔离 DATA_DIR 冒烟（pr52/58/60/62 四面） | 本席历次复算——tmp/ 39 目录留痕 |
| 幂等双跑零触主区（pr60-idem） | PR#60 事故清场核验 |
| 事故反证：主区被触的两次（node_modules 掏空/junction 波及）均因**主区误用**非隔离面泄漏 | wm-pr49 定因 B 案 |

**范本结论**：隔离实例（独立 DATA_DIR+PORT）是可靠的租户边界实验面——本席复算史零隔离面泄漏。

## 四、风险表（S1-S3）

| # | 面 | 风险 | 级 | 现有缓解 | 缺口 |
|---|---|---|---|---|---|
| R1 | 门户代理 | SSRF：/go/ 代理可达内网任意目标（注册面无 URL 白名单） | **S1** | 远程写收口（REMOTE_ALLOW 四白名单） | URL 注册无内网段限制（内网信任模型下可接受，跨信任域前必须补） |
| R2 | 共享 Redis | sop_runs 热态跨「台」共享（无租户键维度）——高负载下热键串扰 | S2 | run_id 键控+30s checkpoint | 无按台分键（单租户语义，多租户形态需评估） |
| R3 | cookie 池 | cookie_set 跨台挂接自由（人工配置可错配） | S2 | 域匹配过滤+过期可见 | 无「池归属台」绑定校验（错配=台 A 注入台 B 的会话票） |
| R4 | MCP 网关 | 会话-上游聚合的授权粒度（taste__* 全量授权不可拆） | S2 | 会话级授权 | 工具级粒度（P5 排期） |
| R5 | endpoint-stats | 键空间无租户维度（/go/:id 归一已有，REST 面共享） | S3 | X-Internal-Probe 豁免+404 不计 | 按台聚合报表需补维度 |
| R6 | SQLite 共库 | 行级 WHERE 键控靠约定（无 RLS） | S3 | 服务层收口（八域 Service 后 index.ts 零直调） | Cordis 化已大幅收口；RLS 属跨信任域前置 |

## 五、评审结论

**单信任域（内网）现状：边界足够**——行级/slug 键控/注入边界三面经 24 台+39 隔离实例实证，无跨租户泄漏事件。
**跨信任域前置清单**（多租户真形态前的必补）：R1 URL 白名单 → R6 RLS 评估 → R3 池归属绑定 → R2 Redis 租户键。
**9877 范本**确立为租户边界实验的标准面（隔离实例=唯一可信实验环境——主区只观测不实验）。
