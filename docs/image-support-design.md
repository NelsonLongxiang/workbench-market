# 数据视图与报告模板支持图片：设计稿（只写文档，待属主定取舍）

状态：设计稿，未实现。依据代码：release/10（b01a3230，基于 main 7a00b5f1）。本稿不改代码；实现属身份、权限与文件上传类，按 CONTRIBUTING 先验后合。

## 0. 为什么写

属主问「数据视图和报告模板什么时候能支持图片」。现在两边都不支持，也没有 issue、PR 或路线图排过。本稿回答五个问题，列出要属主定的取舍；每项给推荐、理由和代价，不替属主定。

## 2. 五个问题的设计

### 2.1 图片存在哪、额度

三条路：

| 方案 | 做法 | 好处 | 代价与风险 |
|---|---|---|---|
| A 台库内 | 台库加素材表，字节存 BLOB | 随台库快照、备份一起走；权限天然按台 | 吃 256MB 合计额度；台库快照每数据集留 5 份，图片进快照会成倍放大；大 BLOB 进工作线程内存 |
| B 台的素材区（推荐） | 字节落盘 dataDir 下的素材目录，台库里只存元数据（sha256、大小、类型、宽高、上传人、状态）；新开按台授权的读路由 | 不占台库数据额度；元数据随台库走；复用现有类型识别、下载头 | 要新路由和新动作（见 2.2）；备份要同时备素材目录与台库（冷备是否整包含 dataDir 下各目录，需确认）；**素材目录不能按 slug 落**（见 W10）：台现在没有 slug 以外的内部 id，要新加一个不复用的台内部 id（或登记序号），删台、清扫、登记三处都要认素材目录 |
| C 对象存储 | 新接 S3 类后端 | 容量大，可 CDN | 仓库没有这套；新凭据、新外联、新运维面；本期不值 |

推荐 B。额度建议（待定）：每张 ≤ 5MB；每台素材合计 ≤ 256MB、≤ 2000 张，与台库数据额度分开计；宽高各 ≤ 8000 像素、像素总数 ≤ 4000 万（挡解码炸弹）。

不推荐直接复用 /api/apps/:slug/files 读图：它按台令牌和管理员判，不按台授权，而且 warn 模式下没有令牌也放行。

### 2.2 谁能上传、谁能看

- 新动作（命名示意）：bench-store.asset-put（上传）、bench-store.asset-read（读）、bench-store.asset-retire（撤）。上传与撤：给能定义数据集或编辑视图的角色（与 dataset-define、view-put 同档）。**撤按角色判，不限定「只有上传人能撤」**：同一个人可能有两个主体（两个账号），只认上传人会让本人换个账号就撤不掉自己误传的图。
- **谁能看：只能选一种判法写死，这是 Q9**。两种判法对「有相邻权限、缺目标权限」的人结果不同：
  - 按台判（读路由判 may(actor, 'bench-store.asset-read', 台)）：只有 report-read、没有 asset-read 的人，报告里的图会碎；只有 asset-read 的人，能读到这个台没被任何视图、报告引用的图，以及已经从视图里去掉的图。
  - 按引用判（读路由带上「从哪份视图或报告来」，核 actor 能读那份视图或报告、且它确实引用了这张图）：权限与读者看到的内容一致；代价是读路由要多一层核对，素材管理页另需按台判的权限。
  - 选哪种，都要列出各预设角色拿不拿得到（只读报告的、只回应的、领域授予的各是什么结果），对抗用例里要有「有相邻权限、缺目标权限」的人（#996 的教训）。
- 素材以「(台, sha256)」为键。读路由路径里带台，只在这个台的素材表里查；查不到与无权回一模一样的应答。写图片列的格子、绑定模板时，核「这个哈希在本台素材表里」（见 W9）。
- 图片只属于一个台。视图、模板只能引用本台的图；**不支持跨台引用**（模板在甲台、图在乙台 → 编译期拒）。
- 跨台报告列表（F）：照 F 的规矩，每台单独判，读不了的台整行不出，它的图也不出；不出「有图但看不见」的占位，免得泄露存在性。
- MCP/AI 上传：走同一动作；MCP 授权（bench-store.mcp-grant）要显式包含 asset-put 才能传。
- 查看凭证 wm_av 这类带在 URL 里的凭证不用于图片：图片走登录会话判权。

### 2.3 报告冻结：内嵌副本还是带哈希的引用

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 引用（推荐） | 冻结报告存 { asset_sha256, 宽高, alt }；素材在**本台内**按 sha256 去重（不跨台去重，上传响应不随别台有没有这张图而变，见 W9）、内容不可改；被冻结报告引用的素材不能物理删，只能「撤」 | 报告行小，不吃 256MB；同图多份报告只存一份；sha256 保证看到的就是冻结时那张 | 素材和报告要一起备份；撤图后旧报告怎么显示要定（见取舍 Q3） |
| 内嵌副本 | 冻结时把字节 base64 写进报告 body | 报告自包含，导出、迁移简单 | 每份报告带全部图片，台库额度很快用完；一次写入 16MB 上限会挡住多图报告；撤图无法从已冻结报告里去掉 |

导出 PDF 时再把图片按 sha256 取出内嵌进 PDF，与冻结存法无关。

### 2.4 格式、大小与活动内容

- 只收 PNG、JPEG、WebP（GIF 待定，见 Q4）。**按内容签名认**，扩展名、上传方报的 MIME 不作数；签名不在白名单就拒（415）。
- **SVG 一律不收**：SVG 可带脚本和外链，净化库是长期攻防面。要矢量图另开题。
- 宽高**纯解析头部**取得（PNG 的 IHDR、JPEG 的 SOF、WebP 的 VP8/VP8L/VP8X），不必解码，挡解码炸弹也不在服务进程里跑解码器。要解码（Q5 选重新编码时），放到单独的工作进程里，限内存、限时。
- 去元数据按「只留像素必需的块」写，不只写「去 EXIF」：EXIF（含其中内嵌的缩略图，裁剪前的原图会留在里面）、XMP、IPTC、ICC、PNG 的 tEXt/iTXt/zTXt 文本块都在范围内。是重新编码还是纯解析剥块，见 Q5。
- 多态文件：签名合法的 PNG 同时可以是 HTML、JS 或 ZIP。nosniff、CSP sandbox、正确的 Content-Type 只能挡它在浏览器里执行，字节原样留着，导出 PDF 时也原样内嵌。重新编码才能消掉它；**Q5 若选不重新编码，这一项就只剩响应头一层防线**，至少要用纯解析剥掉 PNG 文本块和 JPEG 的 COM/APPn 段。
- 读路由的响应头：Content-Type 用入库时认定的类型；X-Content-Type-Options: nosniff；Content-Disposition: inline 只给白名单类型；Content-Security-Policy: default-src 'none'; sandbox；Cross-Origin-Resource-Policy: same-origin；Cache-Control: private（按 sha256 的强 ETag，不进共享缓存）；Referrer-Policy: no-referrer。
- 处理顺序：**先判权限，再处理条件请求**（If-None-Match → 304）。无权、不存在、哈希不在本台，回一模一样的应答（同状态码、同正文、同头），与 F「不暴露存在性」一致。撤图后的 410 只回给有权读的人，其余照「不存在」回（见 W12）。
- 图片只能引用本站素材。**不收外部 URL**：外链会把读者 IP 和 Referer 送到外站，导出 PDF 时服务端去取还会变成 SSRF。
- alt、标题按文本转义，不进 innerHTML。
- 发现：主界面没有 CSP 头。图片本身不靠它，但建议另开一单给主界面加 CSP（至少 img-src 'self'，object-src 'none'），作纵深防御。

### 2.5 数据视图：图片列还是记录卡附件缩略图

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 图片列（推荐） | 列类型加 image，格里存素材 sha256；table 显示小缩略图，records 显示大一点，点开看原图 | 和现有「列 + 块」模型一致；报告数据槽能原样带上（槽列类型 image）；查询、筛选、权限路径不变 | 改列类型要过台库迁移、视图契约、回放面；一格只能一张图 |
| 记录卡附件 | 每行挂若干附件，records 卡里显示缩略图 | 一行可多张，贴近「附件」心智 | 台库行没有附件概念，要新建行→附件关系；报告槽怎么带附件要另设计；表格里放不下 |

## 3. 最坏情况与绕过面

| # | 最坏情况 | 绕过面 | 挡法 |
|---|---|---|---|
| W1 | 没授权的人看到别台图片 | 素材 URL 外传、ID 可猜、复用旧文件面（按令牌不按授权，warn 模式全放行） | 新读路由每次按台 may 判；ID 用 sha256 不用自增号；不复用 /api/apps/:slug/files |
| W2 | 跨台报告露出读不了的台的图 | 模板跨台引用；F 列表只裁行没裁图 | 编译期拒跨台引用；F 按台整行裁剪 |
| W3 | 存储型 XSS | SVG、HTML 伪装成图片、MIME 嗅探；多态文件（合法 PNG 同时是 HTML/JS/ZIP） | 签名白名单、拒 SVG、nosniff、CSP sandbox；多态文件只有重新编码能消掉，否则至少剥文本块与 COM/APPn 段（Q5） |
| W4 | 拖垮服务 | 解码炸弹、海量小图、超大图 | 单张大小与像素上限、每台张数与合计额度、上传限流 |
| W5 | 隐私外泄 | EXIF 里的 GPS、设备号，EXIF 内嵌的缩略图（裁剪前的原图），XMP、IPTC、ICC、PNG 文本块 | 只留像素必需的块（Q5）；至少在上传处提示 |
| W6 | 撤不掉 | 冻结报告引用、导出过的 PDF、浏览器缓存 | 撤图后读路由回 410；缓存 private；已导出的文件撤不回，要写进说明 |
| W7 | 外部取图 | 外部 URL、导出时服务端取图 | 只收本站素材，不收 URL |
| W8 | AI 批量上传垃圾或违规图 | MCP 授权过宽 | asset-put 单列进 MCP 授权；记上传人与 producer_kind |
| W9 | 按哈希串台，去重泄露存在性 | 在乙台有写数据权限的人，往乙台的图片列填甲台图片的 sha256，借乙台的授权看到甲台的图；全站去重时，上传响应（「已存在」或明显变快）泄露「别的台有这张图」 | 素材以 (台, sha256) 为键；读路由带台、只查本台；写格子、绑定模板时核哈希在本台素材表里；去重只在台内，上传响应不随别台变 |
| W10 | 同名台接着用旧台的图 | 素材按 slug 落盘；删台、清扫只删台库文件不碰上传目录；登记处只挡「台库文件还在」（bench-registry.ts:152）。台库清掉后，同一标识新登记的台读到旧台的图 | 素材目录用不复用的台内部 id，不用 slug；删台把素材纳入备份和删除；清扫加孤儿素材；登记处同时核素材目录 |
| W11 | 读权限两种口径互相矛盾 | 按引用判与按台判混用：只有 report-read 的人图碎掉；只有 asset-read 的人读到未被引用、已被去掉的图 | 选一种写死（Q9）；列出各预设角色的结果；对抗用例含「有相邻权限、缺目标权限」的人 |
| W12 | 经缓存与状态码探出存在性 | 先回 304 再判权；不存在回 404、无权回 403；撤图回 410 给任何人 | 先判权再处理条件请求；无权、不存在、哈希不在本台回同一应答；410 只给有权读的人 |
| W13 | 服务端解码被攻破 | 上传时解码核宽高、重新编码，都在服务进程里解析不可信图片（原生库漏洞） | 宽高纯解析头部；要解码就放单独工作进程，限内存、限时 |

## 4. 要属主定的取舍

| # | 要定什么 | 推荐 | 理由 | 代价 |
|---|---|---|---|---|
| Q1 | 图片存哪 | B：字节落盘、元数据进台库、按台授权的新读路由 | 不占台库额度，权限口径与视图、报告一致 | 新路由、新动作、独立验收 |
| Q2 | 额度 | 单张 5MB；每台 256MB、2000 张，与数据额度分开；像素 ≤ 4000 万 | 够报告和记录照片用，挡住滥用 | 高清扫描件、长图放不下 |
| Q3 | 撤图后已冻结的报告 | 允许撤：读路由对有权读的人回 410，报告显示「图片已撤」加哈希 | 能处理误传、隐私投诉 | **改动现有契约**：报告第 1 步用例 9「已冻结的报告逐字不变」（docs/report-step1.md:189）不再成立——冻结的文字和哈希不变，但图片本身可以被撤；报告上要标出。不允许撤则误传的图在冻结报告里永远可见 |
| Q4 | 收哪些格式 | PNG、JPEG、WebP；GIF 不收；SVG 不收 | GIF 动图价值低、解码面大；SVG 是活动内容 | 有人要动图或矢量图时得转格式 |
| Q5 | 上传时是否重新编码 | 甲：重新编码（只留像素，统一方向），放单独工作进程限内存限时；乙（不引依赖的备选）：纯 JS 解析头部取宽高、剥元数据块和文本块，不重新编码 | 甲能消掉多态文件和全部元数据；乙不引新依赖，也没有解码器攻击面 | 甲：**要引入图像处理库，是新增运行时依赖，按 CONTRIBUTING 红线须属主批准**（登记进 tech-route.json 的 deps），原图字节不保留、sha256 是处理后的；乙：多态文件只剩响应头一层防线，剥块逻辑要自己写、要跟着格式细节测 |
| Q6 | 数据视图用哪种 | 图片列（列类型 image） | 与列和块模型、报告槽一致 | 一格一张；多图需求要另做 |
| Q7 | 谁能上传 | 与能定义数据集、编辑视图的角色同档；MCP 要显式授权 | 最小权限 | 普通成员不能在表单里传图（表单传图另议） |
| Q8 | 主界面 CSP | 另开一单补 | 纵深防御，与图片解耦 | 要排查现有内联脚本 |
| Q9 | 谁能看 | 按引用判：能读引用这张图的视图或报告的人才能读；素材管理页另按台的 asset-read 判 | 读者看到的图与他能看的视图、报告一致；不会读到未被引用或已被去掉的图 | 读路由要带来源并核引用，实现与测试更重；按台判更简单，但会出现 W11 的两种错位 |

以下四条本稿按**默认收紧**写，只收紧、不放宽；属主可推翻：
- 不支持跨台引用图片；
- SVG 一律不收；
- 不收外部 URL 图片；
- 下载用查看凭证 wm_av 不用于图片。

## 5. 不在本稿内

表单（form 块）传图；视频、PDF 等其他附件；图片编辑、裁剪；外链图；对象存储；跨台共享素材库。

1. 素材区：存储、上传、读路由、动作与授权、回放面与负向测试，先单独验收。
