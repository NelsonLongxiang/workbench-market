## 2. 属主已定的方向与设计

### 2.0 属主已定

- 图片**只用链接**，链接指向属主准备的**本地图库**。
- **浏览器不访问图库**：由工作台市场在服务端代取，判完权限再交给浏览器。
- **市场访问图库不要凭据，图库就是静态资源链接（Q11）**。这在「图库与市场同机、只绑本机回环」时成立；图库若实际在另一台机器、绑内网地址，见 2.4「图库本身」，要属主另行确认。
- 由此：市场不收上传、不存原图（代取缓存见 Q12）；第一版的方案 B、上传权限、每台素材额度、同名台复用素材目录（原 W10）都不再适用。

### 2.1 链接怎么存、图库怎么配

- 图库地址由部署配置给一个**前缀**（命名示意 WM_IMAGE_GALLERY_BASE，形如 scheme://主机:端口/路径/）。按仓库红线，新环境变量要写进 README。没配就整个功能关着，图片节点、图片列按现在的样子拒。
- 链接只存**图库内的相对路径**（或完整 URL 但入库前规范化并核前缀，二选一，推荐相对路径：换图库地址不用改数据，也不会把图库真实地址带进视图定义和报告）。
- 入库时规范化并核：只允许图库前缀下的路径；拒 userinfo（user@host）、拒反斜杠、拒编码后的「..」（%2e%2e、%2f）、拒查询串和片段（或按白名单留），规范化之后再比前缀。
- 浏览器只拿到市场自己的**代取路径**（命名示意 /api/benches/<台>/images?ref=<来源>&path=<相对路径>），永远拿不到图库真实地址。

### 2.2 谁能写链接、谁能看

- **写**：图片列的格子跟着写数据的权限走（写数据集的人就能填链接）；模板里的图片节点跟着编辑模板、绑定的权限走。不新开上传动作。
- **谁能看（Q9，仍要定）**：
  - 按台判：代取路由判 may(actor, 某个读动作, 台)。
  - 按引用判（推荐）：代取路由带上「从哪份视图或报告来」，**三条都满足才放行**：这份视图或报告属于路径里的这个台；读者能读它；它确实引用了这个链接。来源是调用方给的，三条缺一条都可能被拿来借道。
  - 选哪种，都要列出各预设角色的结果，对抗用例里要有「有相邻权限、缺目标权限」的人（#996 的教训）。
- **图库内容对谁可见（Q10，新，要定）**：链接是全局路径，在某个台有写权限的人可以往格子里填图库里任何一张图的路径（W9 的新形态）。
  - 全公司共享：图库里的图本来就人人可看，市场只判「能不能看这份视图或报告」。简单；但图库里不能放敏感图。
  - 按台隔离：图库按台分目录（路径前缀带台的不复用内部 id，不用 slug——台现在只有 slug，见第 1 节），市场核「这个路径在本台的目录下」。写格子、绑定模板、代取三处都核。
- 跨台报告列表（F）：每台单独判，读不了的台整行不出，它的图也不出。
- 查看凭证 wm_av 不用于图片：代取走登录会话判权。

### 2.3 报告冻结（Q3）

链接背后的图可能被换掉或删掉。冻结时市场代取一次，然后二选一：

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 只记哈希（推荐） | 冻结报告存 { 路径, sha256, 宽高, alt }；以后读时代取并比对，对不上就显示「图片已变」加冻结时的哈希，不显示新图 | 报告行小，不吃台库 256MB 额度；图库仍是唯一存放处 | 图库删了或改了，冻结报告就看不到原图；**改动现有契约**：报告第 1 步用例 9「已冻结的报告逐字不变」（docs/report-step1.md:189）——文字和哈希不变，图可能看不到，报告上要标出 |
| 市场留副本 | 冻结时把取到的字节存进市场（按 (台, sha256)，不跨台去重） | 冻结报告完全可复现，满足用例 9 | 市场又要存图：额度、备份、删台清理、撤图都回来了（第一版的 W10、W6 照旧适用）；一次写入 16MB 上限会挡住多图报告（若存台库） |

导出 PDF 时由市场代取（或取副本）内嵌，浏览器不参与。

### 2.4 代取（主风险是 SSRF，见 W7）

- **只取图库前缀**：相对路径按段编码后拼成最终 URL，**前缀比对放在最终交给 HTTP 客户端的那个 URL 上**，不要比完字符串再交给会二次解析的库，免得规范化前后不一致；只发 GET。
- **不跟随跳转**：3xx 一律当失败；图库要跳就改图库。
- **固定解析出的地址**：解析一次图库主机名，把连接钉到配置里允许的地址上，防 DNS 重绑定（解析结果变了就拒）。推荐图库地址直接配成 IP 加端口。
- **限大小、限时**：按流读，超过单张上限（Q2）立即断开；连接、总时长都有上限；同时进行的代取数有上限。
- **不转发读者的任何东西**：不带读者的 Cookie、Authorization、Referer、X-Forwarded-*；市场访问图库不要凭据（Q11 已定）；以后若改为要凭据，凭据只从部署配置读，不进仓库、不进日志、不进错误信息。
- **对外断开**：WM_OUTBOUND=off 时代取不发起（先问 outboundOff()），回「图片暂不可用」，不当错误重试。
- **取回的字节照样不信**：按内容签名认类型，只收 PNG、JPEG、WebP（Q4）；**SVG 一律拒**；宽高纯解析头部取得（PNG 的 IHDR、JPEG 的 SOF、WebP 的 VP8/VP8L/VP8X），超像素上限拒。
- **去元数据（Q5）**：在图库那边做，还是市场代取时做，要定。按「只留像素必需的块」：EXIF（含内嵌缩略图）、XMP、IPTC、ICC、PNG 的 tEXt/iTXt/zTXt 都在范围内。多态文件（合法 PNG 同时是 HTML/JS/ZIP）只有重新编码能消掉；不重新编码就只剩响应头一层防线。
- **给浏览器的响应头**：Content-Type 用代取时认定的类型；X-Content-Type-Options: nosniff；Content-Disposition: inline；Content-Security-Policy: default-src 'none'; sandbox；Cross-Origin-Resource-Policy: same-origin；Cache-Control: private；Referrer-Policy: no-referrer。
- **处理顺序**：先判权限，再查缓存、处理条件请求（If-None-Match → 304）、去图库取。**没权限的请求根本不去图库**：否则图库会被没权限的人间接打满，「取到」与「没取到」的耗时差也会泄露图在不在。无权、不存在、路径不在允许范围、图库没取到，对没权限的人回一模一样的应答；「图片已变」「图库取不到」只给有权读的人看。
- **图库本身**：读者的浏览器本来就在内网里，「只绑内网」挡不住——内网里的人拿到路径就能直接打开，代取时判的权限就被绕过。所以：
  - 属主已定不要凭据（Q11），这在图库与市场在同一台机器上、图库**只绑本机回环**时成立：浏览器够不着图库。
  - 图库若实际在另一台机器、绑内网地址：内网读者拿到路径可以直连，绕过代取判权。这种部署**要属主另行确认**（接受内网可直连，或改为要凭据，或放在读者机器访问不到的网段），不按 Q11 的「不要凭据」默认放行。
  - 市场侧启动自检照旧：配置的前缀不是回环地址、又没配凭据，就拒绝启用。
- 主界面没有 CSP 头（第 1 节）。图片不靠它，建议另开一单补（Q8）。

### 2.5 数据视图：图片列

- 列类型加 image，格子里存图库相对路径；table 显示小缩略图，records 显示大一点，点开看原图，都走代取路径。
- 写格子时核路径规范、在图库前缀下（Q10 选按台隔离时还要核在本台目录下）。
- 报告数据槽能原样带上（槽列类型 image）。
- 代价：改列类型要过台库迁移、视图契约、回放面；一格一张。记录卡附件方案不再考虑（附件意味着上传，与属主决定不符）。

### 2.6 公网图片链接（属主补充，整类待定）

属主说「还有一些图片链接是公网的」。本节是按这句话写的方案，**整类都待属主定（Q13–Q16），定之前公网地址一律拒**。与已定项的关系：Q1（图库 + 市场代取）和 Q11（图库不要凭据）只管本地图库，不因本节改变；公网链接沿用属主「不经由浏览器访问」：也由市场代取，浏览器不直连外站。

- **存法**：格子和模板里存完整 URL（图库链接仍存相对路径，两类分开存、分开核）。只收 https；是否也收 http 待定（Q15）。
- **先判权限再取**：同 2.4；没权限的请求不去外站。
- **取之前，按解析出的地址判，不按写的字面判**：解析主机名得到的每一个地址都要是公网地址，有一个不是就整条拒。拒的范围：
  - IPv4：回环 127/8、私网 10/8、172.16/12、192.168/16、链路本地 169.254/16（含云元数据 169.254.169.254）、运营商级 NAT 100.64/10、0/8、组播 224/4、保留 240/4、文档与基准网段；
  - IPv6：::1、ULA fc00::/7（含部分云的元数据地址）、链路本地 fe80::/10、组播 ff00::/8，以及 ::ffff:0:0/96 映射地址（按内含的 IPv4 再判一次）。
  - 可以复用 url-admission.ts 现成的 classifyV4、classifyV6（只认 public 一档，private 和 hard 都拒），但要用在**解析出的地址**上——那套代码现在只判登记时的字面地址（第 1 节）。
- **连接钉到已核的地址**：判过的地址直接用来连（给 HTTP 客户端一个只返回这个地址的 lookup），不让客户端自己再解析一遍，防 DNS 重绑定。TLS 仍按原主机名校验证书和 SNI。**仓库现在没有这样的钉址代码（第 1 节），要新写，并且要有对抗用例**。
- **跳转**：推荐不跟（与现有外发一致，3xx 当失败）；若属主要跟，必须逐跳重新走「规范化、判权、解析、判地址、钉址」整套，最多 3 跳，且不许从 https 跳到 http。
- **端口**：只放 443；收 http 才加 80。URL 里写了别的端口一律拒。
- **对外断开**：WM_OUTBOUND=off 时不发起（先问 outboundOff()），回「图片暂不可用」。
- **限额**：同 2.4 的大小、时间、并发上限；公网另加每个外站主机的并发与频率上限，免得市场被拿去打别人的站。
- **不转发读者的任何头**；请求只带固定的 User-Agent 和 Accept，不带 Cookie、Authorization、Referer。
- **取回的字节**：同 2.4，按签名认类型，拒 SVG，宽高纯解析头部；去元数据在市场侧做（外站的图不归属主管，Q5 推荐的「在图库侧做」对公网图不成立），做法见 Q5 的甲、乙。
- **哪些公网地址能用（Q13）**：任意公网地址，还是部署配置的域名白名单。推荐白名单：仓库已有同类先例（WM_REGISTER_URL_ALLOWLIST，第 1 节）；白名单按主机名精确匹配，不做后缀通配。
- **外站的图会变或消失（Q14）**：冻结报告对公网图是只记哈希（同 Q3 推荐，对不上显示「图片已变」），还是冻结时由市场留副本。
- **外站能看到市场服务器（Q16）**：每次代取，外站都能看到市场服务器的出口 IP、取图时间和频率，能据此推断「什么时候有人在看哪份报告」。缓存（Q12）能减少次数，但挡不住第一次。

## 3. 最坏情况与绕过面

| # | 最坏情况 | 绕过面 | 挡法 |
|---|---|---|---|
| W1 | 没授权的人看到图 | 代取路径外传；在内网直接访问图库；复用旧文件面 | 代取按 Q9 定的判法每次判；图库只绑本机回环（Q11 已定不要凭据的前提）；不在同一台机器时要属主另行确认（要凭据或放在读者访问不到的网段），启动自检拒「非回环又无凭据」；真实地址不给浏览器；不复用 /api/apps/:slug/files |
| W2 | 跨台报告露出读不了的台的图 | F 列表只裁行没裁图 | F 按台整行裁剪 |
| W3 | 存储型 XSS | SVG、HTML 伪装成图片、MIME 嗅探、多态文件 | 签名白名单、拒 SVG、nosniff、CSP sandbox；多态文件只有重新编码能消掉（Q5） |
| W4 | 拖垮服务或图库 | 超大图、解码炸弹、海量代取、慢速图库拖住连接 | 单张大小与像素上限；按流读超限即断；连接与总时长上限；并发上限；代取缓存（Q12） |
| W5 | 隐私外泄 | EXIF（含内嵌缩略图）、XMP、IPTC、ICC、PNG 文本块 | 只留像素必需的块，在哪一侧做见 Q5 |
| W6 | 撤不掉 | 冻结报告留副本、导出过的 PDF、浏览器缓存 | 只记哈希时撤图就是在图库删；留副本时要另有撤的动作；缓存 private；已导出的文件撤不回，写进说明 |
| **W7（主风险）** | 市场被当成跳板去访问内网别的服务 | 构造路径逃出前缀（..、编码、反斜杠、userinfo）；图库或中间人回 3xx 指向别处；DNS 重绑定；把读者凭证带过去 | 规范化后核前缀；不跟随跳转；钉死解析地址；不转发读者任何头；只发 GET；限大小限时 |
| W8 | AI 批量写入大量链接拖垮代取 | MCP 写数据授权 | 并发与频率上限；代取缓存；记 producer_kind |
| W9 | 借本台授权看图库里不该看的图 | 在某台有写权限的人往格子里填图库任意路径 | 取决于 Q10：全公司共享时图库不放敏感图；按台隔离时写格子、绑定模板、代取三处核本台目录 |
| W10 | （第一版：同名台复用旧图） | 不再上传、不存图则不适用；Q3 选「留副本」或 Q10 选「按台隔离」时重新适用：目录与副本要按不复用的台内部 id，不按 slug | 同左 |
| W11 | 读权限两种口径互相矛盾 | 按引用判与按台判混用 | 选一种写死（Q9）；列出各预设角色的结果 |
| W12 | 经缓存与状态码探出存在性 | 先回 304 再判权；不存在、无权、图库取不到回不同应答 | 先判权再处理条件请求；对没权限的人同一应答 |
| W13 | 服务端解析被攻破 | 代取后解码、重新编码在服务进程里解析不可信图片 | 宽高纯解析头部；要解码就放单独工作进程，限内存、限时 |
| W14 | 图库凭据泄露（Q11 已定不要凭据，本条只在以后改为要凭据时适用） | 凭据写进仓库、日志、错误信息、回给浏览器的应答 | 只从部署配置读；日志与错误只记路径不记凭据；代取应答不带图库的头 |
| W15 | 公网链接被拿来打内网（SSRF，公网一类放开时） | 主机名解析到私网、回环、元数据地址；DNS 重绑定（判时公网、连时内网）；跳转到内网；IPv4 映射的 IPv6 地址；非标准端口 | 按解析出的全部地址判，只认公网；连接钉到已核地址；不跟跳转（或逐跳全套重核）；只放 443（及 80）；Q13 选白名单进一步收窄 |
| W16 | 外站的图变了或没了 | 外站换图、删图、域名过期被他人注册 | 冻结时记哈希、读时比对（Q14）；或留副本；域名被转手时白名单（Q13）要能及时删 |
| W17 | 外站借取图跟踪 | 外站记录市场出口 IP、取图时间和频率；用唯一 URL 标记某份报告被打开 | 写进说明让属主知情（Q16）；进程内缓存减少次数；白名单只放可信来源 |

## 4. 要属主定的取舍

已定：
- Q1 图片放哪——属主的本地图库，市场代取（2.0）。
- Q11 市场访问图库要不要凭据——**不要凭据，图库是静态资源链接**（属主 2026-11-23）。见下表 Q11 行的前提与代价。

其余各项仍待属主定：

| # | 要定什么 | 推荐 | 理由 | 代价 |
|---|---|---|---|---|
| Q2 | 代取上限 | 单张 5MB；像素 ≤ 4000 万；单次代取 10 秒；同时代取 ≤ 8 | 够报告和记录照片用，挡住慢图库和大图拖垮服务 | 高清扫描件、长图放不下；图库慢时图片先显示不出 |
| Q3 | 冻结报告：只记哈希，还是市场留副本 | 只记哈希，对不上显示「图片已变」 | 图库是唯一存放处，市场不再存图 | **改动现有契约**：报告第 1 步用例 9「已冻结的报告逐字不变」（docs/report-step1.md:189）——图库删了或改了，冻结报告看不到原图。留副本则契约不变，但存储、额度、删台清理、撤图都回来 |
| Q4 | 收哪些格式 | PNG、JPEG、WebP；GIF、SVG 不收 | GIF 价值低、解析面大；SVG 是活动内容 | 动图、矢量图要先转格式再放进图库 |
| Q5 | 去元数据在哪做、怎么做 | 在图库那边做（属主侧入库时处理），市场代取时只核类型与尺寸 | 市场不引图像库、不在服务进程里解码 | 依赖图库那边做到；市场侧要做的话：甲 重新编码（**新增运行时依赖，按 CONTRIBUTING 红线须属主批**，放工作进程限内存限时），乙 纯 JS 剥块（不引依赖，多态文件只剩响应头一层防线） |
| Q6 | 数据视图用哪种 | 图片列（列类型 image，存图库相对路径） | 与列和块模型、报告槽一致 | 一格一张 |
| Q8 | 主界面 CSP | 另开一单补 | 纵深防御，与图片解耦 | 要排查现有内联脚本 |
| Q9 | 谁能看 | 按引用判：来源属于这个台、读者能读它、它确实引用了这个链接，三条都满足 | 读者看到的图与他能看的视图、报告一致 | 代取路由要带来源并核引用，实现与测试更重 |
| Q10 | 图库内容对谁可见 | 先全公司共享，图库不放敏感图；以后有敏感图再按台分目录 | 属主自己管图库，最简单 | 在任何台有写权限的人能引用图库里任何一张图；按台隔离要台有不复用的内部 id，写格子、绑定、代取三处核目录 |
| Q11 | 市场访问图库要不要凭据 | **已定（属主 2026-11-23）：不要凭据，图库是静态资源链接** | 前提：图库与市场同机、只绑本机回环，浏览器够不着图库；启动自检照旧拒绝「非回环又无凭据」 | 同机其他进程（其他会话、其他服务）也能直接读图库——**图库里放敏感图之前，建议改为要凭据**；图库若实际在另一台机器、绑内网地址，内网读者可直连、绕过代取判权，**要属主另行确认** |
| Q12 | 市场是否缓存代取结果 | 只在进程内短时缓存，不落盘；**命中缓存前也先判这个读者的权限**；Q10 选按台隔离时缓存键带台 | 挡海量重复代取，不引入新的存储 | 重启丢缓存；图库改图后最长要等缓存过期才看到 |
| Q13 | 公网图片链接放不放、放哪些（2.6） | 放，但只放部署配置的域名白名单，按主机名精确匹配 | 范围小、可审；仓库已有同类白名单先例 | 新来源要改部署配置；白名单要有人维护（域名过期转手要删）；不放则公网图只能先下载进图库 |
| Q14 | 冻结报告里的公网图：只记哈希还是留副本 | 留副本（只对公网图）；图库图仍按 Q3 | 外站不归属主管，变了或没了无从追回；留副本让冻结报告可复现 | 市场又要存图：额度、备份、删台清理、撤图回来（W10、W6 对这部分适用）；外站图的版权与留存要属主认可 |
| Q15 | 公网链接收不收 http | 只收 https | 明文可被中途篡改换图；TLS 证书校验也能挡一部分重绑定 | 只有 http 的来源用不了 |
| Q16 | 外站能看到市场出口 IP 与取图时间，是否接受 | 接受，写进说明；配合 Q13 白名单与 Q12 缓存 | 代取本来就要从市场出去，挡不住 | 外站可据此推断报告被打开的时间；要彻底挡就得冻结时留副本、平时不去外站取 |

原 Q7（谁能上传）不再适用：不收上传，写链接跟着写数据、编辑模板的权限走（2.2）。

以下三条本稿按**默认收紧**写，属主可推翻：
- 不支持跨台引用图片（模板在甲台、链接指向乙台的目录 → 编译期拒；Q10 选全公司共享时此条只约束「来源属于这个台」）；
- SVG 一律不收；
- 下载用查看凭证 wm_av 不用于图片。

第一版的「不收外部 URL」已被属主推翻，但**只限图库前缀**。公网链接一类（2.6）待 Q13–Q16 定；定之前，图库前缀以外的地址一律拒。

## 6. 落地顺序建议（属主定完再排）

1. 代取：配置、路径规范化、前缀与地址钉死、限额、类型核对、响应头、按 Q9 判权；回放面与对抗用例（W7、W9、W12 各一组），先单独验收。
2. 数据视图：列类型 image 与 table、records 渲染。
3. 报告：模板 v2 的 image 节点收图库相对路径，编译期核规范与本台；冻结按 Q3；导出时市场代取内嵌。
4. 公网链接（Q13–Q16 定了以后才做）：解析后按地址判、钉址连接、跳转策略、端口与每站限额；对抗用例覆盖 W15（私网、回环、元数据、映射地址、重绑定、跳转、非标准端口各一）。
5. 主界面 CSP（独立一单）。
