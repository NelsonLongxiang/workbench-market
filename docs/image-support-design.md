# 数据视图与报告模板支持图片：设计稿（只写文档，待属主定取舍）

状态：设计稿，未实现。依据代码：release/10（b01a3230，基于 main 7a00b5f1）。本稿不改代码；实现属身份、权限与文件上传类，按 CONTRIBUTING 先验后合。

## 0. 为什么写

属主问「数据视图和报告模板什么时候能支持图片」。现在两边都不支持，也没有 issue、PR 或路线图排过。本稿回答五个问题，列出要属主定的取舍；每项给推荐、理由和代价，不替属主定。

## 1. 现状（逐条可核）

| 面 | 现状 | 出处 |
|---|---|---|
| 报告 P0 试验 | 有 image 节点，素材只收内嵌 PNG data URL 加 sha256，只用于网页打印试验 | web/src/report-template/p0.ts:21、:188 |
| 报告正式生成 | 「图片节点这一步不收：素材怎么授权还没定……遇到就拒」 | server/src/services/report-compile.ts:9 |
| P0 结论 | 「尚未证明」里有「资产授权」 | docs/report-template-p0.md:68 |

| 台库额度 | 单数据集 32,000,000 字节，一台在用合计 256,000,000 字节，一次写入 16,000,000 字节（十进制 MB） | server/src/bench-query.ts:21 |

要点：现有「台的文件面」能存图片，下载头也够严，但**读权限不按台授权判**。图片一旦进了数据视图和报告，看的人是按台授权进来的，两套口径对不上。这就是 P0 说的「资产授权」缺口。

## 2. 五个问题的设计

### 2.1 图片存在哪、额度

三条路：

| 方案 | 做法 | 好处 | 代价与风险 |
|---|---|---|---|
| A 台库内 | 台库加素材表，字节存 BLOB | 随台库快照、备份一起走；权限天然按台 | 吃 256MB 合计额度；台库快照每数据集留 5 份，图片进快照会成倍放大；大 BLOB 进工作线程内存 |
| B 台的素材区（推荐） | 字节落盘 dataDir/uploads（同现有布局），台库里只存元数据（sha256、大小、类型、宽高、上传人、状态）；新开按台授权的读路由 | 不占台库数据额度；元数据随台库走；复用现有落盘、类型识别、下载头 | 要新路由和新动作（见 2.2）；备份要同时备 uploads 与台库（现有冷备已整包 dataDir，需确认） |
| C 对象存储 | 新接 S3 类后端 | 容量大，可 CDN | 仓库没有这套；新凭据、新外联、新运维面；本期不值 |

推荐 B。额度建议（待定）：每张 ≤ 5MB；每台素材合计 ≤ 256MB、≤ 2000 张，与台库数据额度分开计；宽高各 ≤ 8000 像素、像素总数 ≤ 4000 万（挡解码炸弹）。

不推荐直接复用 /api/apps/:slug/files 读图：它按台令牌和管理员判，不按台授权，而且 warn 模式下没有令牌也放行。

### 2.2 谁能上传、谁能看

- 新动作（命名示意）：bench-store.asset-put（上传）、bench-store.asset-read（读）、bench-store.asset-retire（撤）。上传与撤：给能定义数据集或编辑视图的角色（与 dataset-define、view-put 同档）。读：凡能读引用它的视图（view-get）或报告（report-read）的人都能读——读路由按「这张图属于哪个台」判 may(actor, 'bench-store.asset-read', 台)，不靠 URL 难猜。
- 图片只属于一个台。视图、模板只能引用本台的图；**不支持跨台引用**（模板在甲台、图在乙台 → 编译期拒）。
- 跨台报告列表（F）：照 F 的规矩，每台单独判，读不了的台整行不出，它的图也不出；不出「有图但看不见」的占位，免得泄露存在性。
- MCP/AI 上传：走同一动作；MCP 授权（bench-store.mcp-grant）要显式包含 asset-put 才能传。
- 查看凭证 wm_av 这类带在 URL 里的凭证不用于图片：图片走登录会话判权。

### 2.3 报告冻结：内嵌副本还是带哈希的引用

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 引用（推荐） | 冻结报告存 { asset_sha256, 宽高, alt }；素材按 sha256 去重、内容不可改；被冻结报告引用的素材不能物理删，只能「撤」 | 报告行小，不吃 256MB；同图多份报告只存一份；sha256 保证看到的就是冻结时那张 | 素材和报告要一起备份；撤图后旧报告怎么显示要定（见取舍 Q3） |
| 内嵌副本 | 冻结时把字节 base64 写进报告 body | 报告自包含，导出、迁移简单 | 每份报告带全部图片，台库额度很快用完；一次写入 16MB 上限会挡住多图报告；撤图无法从已冻结报告里去掉 |

导出 PDF 时再把图片按 sha256 取出内嵌进 PDF，与冻结存法无关。

### 2.4 格式、大小与活动内容

- 只收 PNG、JPEG、WebP（GIF 待定，见 Q4）。**按内容签名认**，扩展名、上传方报的 MIME 不作数；签名不在白名单就拒（415）。
- **SVG 一律不收**：SVG 可带脚本和外链，净化库是长期攻防面。要矢量图另开题。
- 上传时解码一次核宽高（挡解码炸弹）；是否重新编码、去 EXIF 见 Q5。
- 读路由的响应头：Content-Type 用入库时认定的类型；X-Content-Type-Options: nosniff；Content-Disposition: inline 只给白名单类型；Content-Security-Policy: default-src 'none'; sandbox；Cross-Origin-Resource-Policy: same-origin；Cache-Control: private（按 sha256 的强 ETag，不进共享缓存）；Referrer-Policy: no-referrer。
- 图片只能引用本站素材。**不收外部 URL**：外链会把读者 IP 和 Referer 送到外站，导出 PDF 时服务端去取还会变成 SSRF。
- alt、标题按文本转义，不进 innerHTML。
- 发现：主界面没有 CSP 头。图片本身不靠它，但建议另开一单给主界面加 CSP（至少 img-src 'self'，object-src 'none'），作纵深防御。

### 2.5 数据视图：图片列还是记录卡附件缩略图

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 图片列（推荐） | 列类型加 image，格里存素材 sha256；table 显示小缩略图，records 显示大一点，点开看原图 | 和现有「列 + 块」模型一致；报告数据槽能原样带上（槽列类型 image）；查询、筛选、权限路径不变 | 改列类型要过台库迁移、视图契约、回放面；一格只能一张图 |
| 记录卡附件 | 每行挂若干附件，records 卡里显示缩略图 | 一行可多张，贴近「附件」心智 | 台库行没有附件概念，要新建行→附件关系；报告槽怎么带附件要另设计；表格里放不下 |

## 3. 最坏情况与绕过面

| # | 最坏情况 | 绕过面 | 挡法 |
|---|---|---|---|
| W1 | 没授权的人看到别台图片 | 素材 URL 外传、ID 可猜、复用旧文件面（按令牌不按授权，warn 模式全放行） | 新读路由每次按台 may 判；ID 用 sha256 不用自增号；不复用 /api/apps/:slug/files |
| W2 | 跨台报告露出读不了的台的图 | 模板跨台引用；F 列表只裁行没裁图 | 编译期拒跨台引用；F 按台整行裁剪 |
| W3 | 存储型 XSS | SVG、HTML 伪装成图片、MIME 嗅探 | 签名白名单、拒 SVG、nosniff、CSP sandbox |
| W4 | 拖垮服务 | 解码炸弹、海量小图、超大图 | 单张大小与像素上限、每台张数与合计额度、上传限流 |
| W5 | 隐私外泄 | 照片 EXIF 里的 GPS、设备号 | 去元数据（Q5）；至少在上传处提示 |
| W6 | 撤不掉 | 冻结报告引用、导出过的 PDF、浏览器缓存 | 撤图后读路由回 410；缓存 private；已导出的文件撤不回，要写进说明 |
| W7 | 外部取图 | 外部 URL、导出时服务端取图 | 只收本站素材，不收 URL |
| W8 | AI 批量上传垃圾或违规图 | MCP 授权过宽 | asset-put 单列进 MCP 授权；记上传人与 producer_kind |

## 4. 要属主定的取舍

| # | 要定什么 | 推荐 | 理由 | 代价 |
|---|---|---|---|---|
| Q1 | 图片存哪 | B：字节落盘、元数据进台库、按台授权的新读路由 | 不占台库额度，权限口径与视图、报告一致 | 新路由、新动作、独立验收 |
| Q2 | 额度 | 单张 5MB；每台 256MB、2000 张，与数据额度分开；像素 ≤ 4000 万 | 够报告和记录照片用，挡住滥用 | 高清扫描件、长图放不下 |
| Q3 | 撤图后已冻结的报告 | 允许撤：读路由回 410，报告显示「图片已撤」加哈希 | 能处理误传、隐私投诉 | 冻结报告不再完全可复现，要在报告上标出 |
| Q4 | 收哪些格式 | PNG、JPEG、WebP；GIF 不收；SVG 不收 | GIF 动图价值低、解码面大；SVG 是活动内容 | 有人要动图或矢量图时得转格式 |
| Q5 | 上传时是否重新编码去 EXIF | 重新编码（去元数据、统一方向） | 挡 GPS 泄露和畸形文件 | 引入图像处理依赖（需评估，新原生依赖）；原图字节不保留、sha256 是处理后的 |
| Q6 | 数据视图用哪种 | 图片列（列类型 image） | 与列和块模型、报告槽一致 | 一格一张；多图需求要另做 |
| Q7 | 谁能上传 | 与能定义数据集、编辑视图的角色同档；MCP 要显式授权 | 最小权限 | 普通成员不能在表单里传图（表单传图另议） |
| Q8 | 主界面 CSP | 另开一单补 | 纵深防御，与图片解耦 | 要排查现有内联脚本 |
