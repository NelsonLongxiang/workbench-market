# 数据视图：模块化的渲染组件 + 每台一份数据

> 属主 2026-11-11 定方向：工作台不再一台一份手写页面。市场提供一组模块化的数据视图组件，台只管「往里填数据」；数据经 MCP 更新；每个工作台有自己的一份库。改台不走评审：各团队改自己团队范围内绑定的工作台，靠版本化管理兜底（原话：「大家可以各自修改自己团队范畴内绑定的工作台」「做好版本化管理方案就行」）。开源项目（Datasette、SQLPage、Evidence 等）只作参考，自己做。本篇是设计稿，还没开工。

## 一、要解决什么

现在一个自产台就是一份 HTML：布局、样式、提交逻辑、读数据的脚本都在里面。同一件事在每个台各写一遍，各错一遍。改一处规矩，要改所有台。

换成三样东西：

| 东西 | 谁提供 | 多久变一次 |
|---|---|---|
| 组件：表格、指标卡、图表、表单…… | 市场，做一次 | 很少 |
| 视图描述：这个台摆哪些组件、各读哪份数据 | 台所属团队的人和 AI 成员，一份 JSON | 偶尔 |
| 数据 | agent 经 MCP 写，人经表单写 | 经常 |

台里不再有 HTML 和脚本。提交、幂等、留痕、无障碍、读不到时怎么说，都在组件里做一次。

这是一种新的台，下文叫**视图台**。现有的 HTML 台和它的规矩（只从仓库 main 同步）不变，两种并存。

## 二、数据：每台一份库

- 每个视图台一份自己的库，和市场主库分开。轻量部署下是数据目录里的一个 SQLite 文件，一台一个。
- 这个台的全部内容都在这份库里：数据集、列定义、视图描述、它们的历史版本、写入记录。主库里只留登记（有这个台、属于哪个团队、当前生效的是哪一版）。所以备份、搬走、删除一个台，就是处理一个文件。
- 库里放的是**数据集**：有名字、有列定义的表。列有名字、类型（文本、整数、小数、日期、时间、布尔）和可选的显示名。
- 一台坏了不连累别的台。

**和「后面换 PostgreSQL」怎么相容**（见产品化文档 13）：台的作者和 agent 都**不写 SQL**。读用第四节的小查询描述，写用第三节的工具。SQLite 只是轻量部署下的存法；企业部署下同一套接口后面换成 PostgreSQL，每台一个 schema。验收办法和文档 13 一样：同一组请求，两种存法应答相同。

**和「表结构只在 `db.ts` 里改」怎么相容**：主库照旧。台的库是另一样东西，由一个专门的数据集服务管，只有它能建表改表，而且只碰台的库。体检里给它单立一项计数。

限额（防一个台把磁盘写满）：每台数据集个数、每个数据集的行数和列数、单次写入的行数、库文件大小、保留的历史版本数，都有上限，超了拒收并说清超的是哪一项。具体数字开工时定。

## 三、谁能改

- 每个视图台绑定到一个团队范围（权限模型里的授权域，范围写法 `domain:<名>`）。建台、把台绑到哪个团队，由管理员或该团队的负责人做。
- 绑定之后，对这个台有写权限的都能改它的数据和视图，不需要评审：授予范围是这个台（`bench:<slug>`）、这个台所属的团队（`domain:<名>`）或全部的人，以及这些团队的 AI 成员。AI 成员照现有判定的规矩：自己有这项授予，并且它的责任人也有。
- 别的团队的人和 AI 成员改不了，能不能看由读权限定。
- MCP 工具的授权照旧可以限定到单个台（`工具@台`）。

现状和要补的：判定现在只把范围是「全部」的授予算作覆盖，还不会按一次请求落在哪个台来判；台上也还没有「属于哪个团队」这个属性。这两样在第二步里补，补之前要和身份线对齐，不各做一套。

## 四、写数据

新增一组 MCP 工具：

| 工具 | 做什么 |
|---|---|
| `dataset_define` | 建数据集，或改列定义。加列、改显示名随时可以；删列、改类型会先自动留一份快照（见第七节） |
| `dataset_replace` | 整份替换：给全部行，原子切换。适合「每次算好一整份」的快照式数据 |
| `dataset_upsert` | 按主键列有则改、无则加。适合增量 |
| `dataset_append` | 只追加。适合流水 |
| `dataset_delete_rows` | 按主键删行 |
| `dataset_query` | 用第五节的查询描述读，和页面读到的一样 |
| `dataset_list` | 列出本台的数据集、列定义、行数、上次更新时间和更新者 |

规矩：

- 每行按列定义校验，不合格整批拒收，逐条说明哪一行哪一列。
- 写入带幂等键；同键同内容返回原结果，同键不同内容拒绝。
- 每次写入留一行记录：谁、哪个数据集、哪种操作、多少行、内容摘要。只记摘要，不记内容。
- 写入后发一个事件，开着的页面据此刷新。
- 工具里不收 SQL，不收文件路径。

人在页面上通过表单组件提交，走的是同一个数据集服务，同样校验、同样留痕。

## 五、读数据：小查询描述，不写 SQL

组件读数据时给一份描述：

```json
{
  "dataset": "runs",
  "filter": [{ "col": "month", "op": "=", "value": "$month" }],
  "group": ["status"],
  "measures": [{ "as": "n", "fn": "count" }, { "as": "total", "fn": "sum", "col": "amount" }],
  "sort": [{ "col": "n", "dir": "desc" }],
  "limit": 50
}
```

- 比较符：等于、不等、大于小于、在列表内、为空、包含。
- 聚合：计数、求和、平均、最大、最小、去重计数。
- `$名字` 引用页面上筛选栏的当前值。
- 行数有硬上限，查询有时限。列名、数据集名只认已定义的，其余一律拒绝；服务端把描述翻成参数化语句，值不拼进语句。

先不支持连表。真要跨数据集，由写入方算好再写一份。

## 六、视图描述

每台一份视图描述，存在台自己的库里，经 MCP 工具或页面上的编辑入口改：

```json
{
  "title": "示例台",
  "views": [
    { "key": "overview", "title": "总览", "blocks": [
      { "type": "filter-bar", "fields": [{ "name": "month", "kind": "month", "default": "last-month" }] },
      { "type": "stat", "title": "本月完成", "query": { "dataset": "runs", "measures": [{ "as": "v", "fn": "sum", "col": "done" }] }, "value": "v" },
      { "type": "bar", "title": "按状态", "query": { "dataset": "runs", "group": ["status"], "measures": [{ "as": "n", "fn": "count" }] }, "x": "status", "y": "n" },
      { "type": "table", "title": "明细", "query": { "dataset": "runs", "limit": 200 }, "columns": ["started_at", "status", "done", "failed"] }
    ] },
    { "key": "report", "title": "提报", "blocks": [
      { "type": "form", "dataset": "reports", "fields": ["title", "kind", "note"] }
    ] }
  ]
}
```

- 一个台有一到多个视图，对应顶栏的菜单项；每个视图是一列组件，按 12 栏网格排。
- 保存时校验：组件类型认得、数据集和列存在、查询合法。不合格就拒，不产生新版本，逐条说明哪里不对。评审没有了，这道校验就是不让坏描述上线的那一关。
- 表单的字段规则沿用现有数据契约的写法（必填、枚举、格式、条件规则），不另造一套。

工具：

| 工具 | 做什么 |
|---|---|
| `view_get` | 读当前生效的视图描述，或指定的某一版 |
| `view_put` | 保存一份新的视图描述，成为新版本并生效 |
| `view_versions` | 列出历史版本：版本号、谁、什么时候、说明、改了什么 |
| `view_diff` | 两个版本之间的差异 |
| `view_rollback` | 让某个旧版本重新生效 |

## 七、版本化管理

不走评审之后，出错靠版本兜底：每一次改动都留得下、看得清、退得回。

**视图描述**

- 每次保存产生一个新版本，版本不可改：版本号、内容、内容摘要、谁改的（人或 AI 成员）、什么时候、一句说明（必填）。
- 当前生效的是哪一版，是一个指针。回退只移指针，不产生新版本、不删任何版本；退错了再移回来。
- 保存时要带上「我是基于第几版改的」。如果这期间别人已经存了新版本，拒绝并返回最新版，由改的人合并后再存。两个人同时改，不会有一方被悄悄盖掉。
- 页面上能看任何一版的效果（预览，不生效），能看两版之间的差异。
- 保留最近若干版（数字开工时定）；被回退指向的版本不清理。

**列定义**

- 列定义的每次改动同样是一个版本，和视图描述分开计。
- 删列、改类型是破坏性的：做之前自动给这个数据集留一份快照。

**数据**

- 数据不逐行留历史（量太大）。留的是写入记录：谁、何时、哪种操作、多少行、内容摘要。
- 整份替换保留前几代，可以一步退回上一代。
- 破坏性操作（按主键删行、删列、改类型）之前自动留快照。也可以手工留快照。快照有个数上限，旧的先清。
- 追加和按主键更新不自动留快照；要退回只能退到最近一份快照，再由写入方重放之后的数据。这是为了不让快照撑满磁盘，写在明处。

**整台**

- 导出：一个台可以导出成一个包（视图描述和它的版本、列定义、可选带数据），再导入到同一个或另一个部署。用途是备份、搬家、从一个台起一个新台。
- 删除整个台不在「不用评审」之内：仍走现有的人审规矩。

**留痕与通知**

- 每次版本变化（保存、回退、列定义变更、退回上一代数据）都记一条：谁、哪个台、从哪版到哪版。
- 变化之后给这个台所属团队的负责人发一条通知，事后可见。这不是审批，不拦。

## 八、组件

所有组件吃同一种数据形状：**一组行，加一份列的角色**（哪列是分类、哪列是数值、哪列是系列）。同一份数据换个组件就能换一种看法。

每个组件自带四种状态：读取中、有数据、没有数据、读不到。读不到要明说原因，不显示成「没有数据」。颜色、字号、间距只用设计 token；成功、警告、危险的颜色语义固定，台不能自己配色。只按桌面宽屏设计。图表都有等价的表格视图，读屏和键盘可用。

图表用 Apache ECharts（Apache-2.0）打底，按需引入，只封装成下面的统一组件，不把它的配置项直接暴露给视图描述。

| 批次 | 组件 |
|---|---|
| 第一批 | 指标卡、数据表格、柱状图（含分组、堆叠、横向）、折线图（含面积）、饼图与环形图、进度条、筛选栏、表单 |
| 第二批 | 漏斗图、金字塔图、瀑布图、日历热力图、排行榜、柱线组合图、状态徽章、详情卡、文件清单、时间线 |
| 按需 | 桑基图、甘特图、透视表、热力矩阵、散点与气泡图、雷达图、直方图、箱线图、矩形树图、仪表盘、子弹图、看板、树 |

## 九、页面怎么出

视图由市场自己的前端渲染，是市场的一个页面，不再是沙箱里的一份外来 HTML：

- 不需要给页面注入台令牌；看得到看不到由登录的人的权限判定，和别的页面一样。
- 提交时知道是谁提交的，不用再让页面带票据。
- 数据只当数据渲染，一律转义；视图描述里不能放 HTML 和脚本。

老的 HTML 台一个一个迁，迁完一个删一个。报告类页面不在迁移范围内。

## 十、分步

1. **本篇定稿。**
2. **数据集服务、视图与版本、MCP 工具。** 服务、限额、留痕、事件；台的团队绑定和按台判定（和身份线对齐）；对抗组（越权改别的团队的台、超限、坏行、注入形态的列名和值、并发保存、回退）；启动自检加一行。
3. **第一批组件和视图页。** 先用合成数据把八个组件做出来，在浏览器里逐个看过。图表库在这一步登记为运行时依赖。
4. **试点一个台。** 选一个现有的台照新形态重做，新旧并排对一遍数。选哪个台记在私有仓。
5. **第二批组件**，以及老台逐个迁移。

每一步单独成 PR；第 2 步动鉴权和写入面，按安全面的规矩走。
