# 04 · 市场与 DSH Web GUI 的关系

> 阶段 0 草稿。回答：业务同事、操作者在两个界面之间怎么走，各自看什么，不重复造什么。

## 一、两者本来是什么

| | DSH Web GUI | 工作台市场 |
|---|---|---|
| 范围 | 一台 DSH 实例：这一个席位 | 跨实例：整个 agent 组织 |
| 用户 | 席位的操作者（属主、运维、开发） | 业务同事、审核人、管理员 |
| 核心对象 | 会话：对话、计划、目标、审批、产物、子代理、定时任务、文件、终端、浏览器 | 事项、事件、台、SOP、授权、证据 |
| 扩展方式 | 客户端插件注册进 slot：左侧栏、右侧栏标签、dockkit 停靠布局；宿主插件经 `ctx.webServer` 挂路由 | 自产台、SOP 台、MCP 工具、扩展挂载点 |
| 视觉 | `ui-theme` 的 `--dsw-*` 色阶 + `--dsw-alias-*` 语义别名，明暗双主题，CSS Modules，无组件库 | `DESIGN.md` 的 `--wm-*`，antd 5，仅浅色 |
| 权限面 | 极高：能开终端、跑 shell、读写工作区 | 有登录门、沙箱、授权分档、审计 |

## 二、定位

- **市场是组织层**：人在这里看全局、下达、决定、验收。
- **DSH GUI 是席位层**：要看清或接管某个席位具体怎么干活时才进去。
- 两层是同一个产品家族，**靠深链互通，功能不重复**。

## 三、四条连接

| # | 方向 | 做什么 | 实现 | 谁能用 |
|---|---|---|---|---|
| C1 | 市场 → DSH | 席位卡「进入席位」，直接打开那台实例里对应的会话或工单 | 新增工作台类型 `dsh-instance`（登记 GUI 基址与会话深链模板）；经门户打开 | **只给操作者角色** |
| C2 | DSH → 市场（只读汇总） | 业务同事在市场看工单时间线和产物，不进 DSH GUI | 事项表汇总 A2A 回执、superagent report、产物入台（见 [02](02-concept-model.md)、[06](06-a2a-superagent-fusion.md)） | 所有能看该事项的人 |
| C3 | 市场 → DSH 内嵌 | 席位操作者在 DSH 里看到业务上下文：本席位绑定的台、待处理事件、被要求注意的事，一键打开台 | DSH 客户端插件 `workbench-market`：注册左侧栏面板 + 右侧栏标签；读市场 MCP / REST（只读） | 席位操作者 |
| C4 | DSH 产物 → 市场 | 会话产物一键「入台」，进入审核与沉淀 | 插件按钮调市场 MCP `app_data_submit` / `app_files_upload`（带 `idempotency_key`） | 席位操作者（按 MCP 授权） |

### C1 的前置条件（硬要求）

DSH GUI 的权限面远大于市场，深链进去等于把席位的控制权交出去。上线 C1 前必须同时满足：

1. **按台、按角色的访问控制**：`dsh-instance` 类型的台只有被授予「操作者」角色的个人身份能打开；其他人看到的是 C2 的只读工单视图。门户层校验，不靠前端隐藏。
2. **凭据不经市场转交**：DSH 的控制面密钥不登记进市场的凭据注入；操作者在 DSH 自己的登录面认证。
3. **审计**：每次深链打开记一行（谁、哪个实例、哪个会话、何时）。

不满足就只做 C2、C3、C4，C1 推迟。

### C3 插件的边界

- 只读：插件不在 DSH 里改市场状态（入台走 C4，且经 MCP 授权）。
- 身份：插件用该席位自己的市场 MCP 会话令牌（已有机制），不新增凭据形态。
- 版本：插件是 DSH 客户端插件，依赖 DSH 预稳定的 slot API，要随 DSH 版本钉住，进系统清单。
- 形态：阶段 1 只做静态数据原型（在体验席上装），阶段 2 接真实数据。

## 四、视觉统一

两个界面会互相嵌（市场的台进 DSH 右栏标签，DSH 会话进市场驾驶舱的席位窗），看起来要是一家人：

- Token v2 的语义层按 DSH `--dsw-alias-*` 对齐命名，给出一张映射表（见 [05](05-token-v2.md)）。
- 市场继续用 antd，但颜色、圆角、阴影、字号都从同一套语义取值。
- 发丝线（0.5px）、用阴影代替描边的高层表面等 DSH 规则，市场在嵌入场景下遵守。

## 五、明确不做

- 不把 DSH 的对话界面复制进市场。
- 不让业务同事进 DSH GUI。
- 不把市场改写成 DSH 插件（系统定义已裁定市场保持独立进程）。
- 不在市场里重做 dockkit 之外的 DSH 能力（文件、终端、浏览器）。

## 待决

- **P1**：DSH GUI 深链开放给哪些角色。建议只开放给属主、运维、开发席。
- **P1**：按台按角色的访问控制是市场门户的新权限语义，实现前需确认（阶段 1 实现，C1 依赖它）。
- P2：C3 插件放哪个仓（建议放市场仓的 `extensions/` 或独立包，阶段 1 定）。
