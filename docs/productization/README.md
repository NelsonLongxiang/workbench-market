# 产品化 · 阶段 0（产品定义与契约）

> 状态：**草稿**（2026-11-10 起草，阶段 0 计划 11-11 ～ 11-17 收口）。
> 本目录只放平台层的定义和契约，可以公开；业务场景、席位所在节点、指标基线放在私有的台仓库，不进本仓。

## 为什么有这一组文档

工作台市场从「登记 + 门户 + 自产台 + SOP」走向产品化。阶段性终局是：

- **体验版**：以模拟数据为准的完整界面，不是最终的产品和样式；
- **agent DSH 实例预演**：用真实的 DSH 实例（装 a2a-net 与 superagent）走一遍「下达 → 席位执行 → 产物入台 → 人审 → 沉淀」。

产品化不是只改界面。市场是 agent 组织的人用入口，它和 DSH、A2A、superagent、ygl-trees 的接缝决定了体验上限，所以阶段 0 先把这些接缝写成契约。

## 已裁定（属主，2026-11-10）

1. 先建基础架构：宿主和几个核心部件。业务和验证器在它上面逐步生长，现在不规划。
2. 基础架构交付的是生长环境，不是功能。
3. 生命周期是系统的观测层：把系统和公司结合起来看的那一层。它不在公开仓。
4. 整套系统建在 Cordis 之上，不脱离。
5. 身份的实现从核心剥离；登录只留一层，用飞书直连；用户、角色、权限自己管。
6. 进入实现：规划任务、设定目标、执行，按阶段验收（计划见 [12](12-implementation-plan.md)）。
7. 约束系统各检查的档位按建议开：没有存量的进红线，有存量的进预算；落点还没建好的先计数。
8. 阶段验收交给并行的独立会话，不等属主。

裁定记在这里，是为了让别的会话读得到：只留在某个会话记忆里的裁定，对别的会话不存在。
