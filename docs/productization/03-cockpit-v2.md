# 03 · 驾驶舱 v2 与信息架构

> 阶段 0 草稿。驾驶舱 v2 是体验版的主工作区，阶段 1 先在体验版里用模拟数据实现，验证后再回到市场前端。

## 一、现状（2026-11-10 实测）

环境：本仓 main 的代码，干净数据目录，1440×900，一个驾驶舱拼三个面板。代码：`web/src/pages/Cockpit.tsx`（374 行）、`web/src/cockpit-layout.ts`。

| # | 问题 | 证据 |

## 二、信息架构

一级导航从「工具清单」改成「人要做的事」：

| 模块 | 内容 | 现有对应 |
|---|---|---|
| 关注 | 待我决定、待我审核、阻塞；一次只问一件事 | 待属主看板、评审页、变更申请（分散） |
| 驾驶舱 | 按场景的作战室（本文主体） | `/cockpit`（重做） |
| 事项 | 全部事项的列表与时间线 | 统一待办 `/tasks`、任务中心（合并到事项视图） |
| 组织 | 节点、席位卡、canvas 团队、名额、健康 | 无（新增） |
| 市场 | 台、SOP、Skills、MCP | `/market`、`/sops`、`/skills` |
| 管理 | 授权、凭据库、类型、设置、事件中心、连接向导 | `/mcp-gateways`、`/vault`、`/types`、`/settings` |

首页是「关注」，不是总览统计。

## 三、驾驶舱 v2

### 1. 整屏工作区

进入驾驶舱后侧栏和页头收起，只留 40px 顶条：

```
[驾驶舱切换 ▾] [场景上下文：店铺 · SKU · 日期 ×]        [● 3 待注意] [值班席：xxx ●] [下达…] [⋯]
```

只读提示不再占一整条，改成顶条右侧一个锁形标记，悬停说明。

### 2. 停靠布局

- 一格可以放多个标签页；分屏、拖放到上下左右中五个方向、最大化、浮动、加减标签页。
- 快捷键：⌘K 切换驾驶舱；⌘1–9 聚焦面板；F 最大化当前面板；Esc 退出最大化。
- 布局引擎：**优先评估复用 DSH 的 `@deepseek-ai/dsh-client-ui-dockkit`**（分裂树 + 标签格 + 可逆操作 + 线性历史，文档写明可被其他应用嵌入），交互和 DSH 一致。它的导出不承诺稳定，要钉版本；若无法脱离 DSH 客户端单独运行，改用成熟的 React 停靠布局库，交互规则照 dockkit 抄。评估结论在阶段 1 第一周给出（P2）。

### 3. 四类面板

| 类型 | 内容 | 数据从哪来 |
|---|---|---|
| 原生部件 | 关注队列、事项时间线、席位状态与名额、台数据指标、SOP 运行进度、验证器结论、健康 | 市场 REST（事项、台数据、变量、A2A 健康） |
| 台视图 | 台按「面板模式」渲染某个子视图 | 自产台 / SOP 台，见下文契约 |
| 席位窗 | 某个 DSH 会话，只给操作者 | 经门户深链 DSH GUI（见 [04](04-dsh-gui-relationship.md)） |
| 外部台 | 旧方式整页 iframe，保留兼容 | `/go/<id>/` |

### 4. 面板状态

每个面板都有明确状态，不再白屏：

| 状态 | 显示 | 处理办法 |
|---|---|---|
| 加载中 | 骨架屏 | — |
| 禁止内嵌 | 「对方禁止被嵌入」 | 新窗口打开 |
| 未授权（401/403） | 「需要登录或授权」 | 去登录 / 申请授权 |
| 找不到（404） | 「地址不对或台已下线」 | 管理员修正登记 |
| 离线 | 「探测失败」+ 上次在线时间 | 查看健康 |

面板头带：待办数、告警点、上次刷新时间。

### 5. 个人驾驶舱与团队模板

- 每人按自己的身份（`odoo:<登录名>`）保存自己的驾驶舱，自己能改。
- 管理员发布「场景模板」（例如运营早会、新品立项、售后），个人一键套用后再改。
- 现有全站驾驶舱迁移为模板。

### 6. agent 进驾驶舱

- 每个驾驶舱可以绑定一个值班席位或团队。
- 顶条「下达…」生成事项，自动带上场景上下文。
- 席位的 report 进事项时间线面板；ask 进关注队列；产出落到对应的台视图面板。

### 7. 不丢状态

面板按需加载；切换驾驶舱时已打开的面板保持挂载（有上限，超过按最久未用卸载）。

## 四、契约：台面板模式

台（自产台、SOP 台）支持被驾驶舱以面板方式嵌入：

- 驾驶舱用 `?wm_panel=1#/<route>/<sub>` 打开台。结构规范 v1.0 已要求台用顶栏 `header.mp-bar` + 哈希路由，所以子视图天然可深链。
- 台看到 `wm_panel=1` 时：隐藏 `header.mp-bar`，使用紧凑密度（行高、留白按 Token v2 的 compact 档），不弹全屏对话框。
- 台不支持面板模式时，驾驶舱按「外部台」方式整页嵌入，并在面板头标注「整页」。
- 支持情况由台自己声明：在 `data-contract.json` 旁的台元数据里加 `panel: { routes: ["…"] }`（阶段 1 定字段，P2）。

## 五、契约：场景上下文总线

台在不透明源沙箱里，只能用 `postMessage`。约定一组消息，驾驶舱是总线中心：

| 方向 | 消息 | 内容 |
|---|---|---|
| 驾驶舱 → 面板 | `wm:context` | `{ v: 1, context: { shop?, sku?, pd?, date?, run? }, rev }` |
| 面板 → 驾驶舱 | `wm:select` | `{ v: 1, patch: { sku: "…" } }`：面板里选中对象，请求改上下文 |
| 面板 → 驾驶舱 | `wm:badge` | `{ v: 1, count, level: "info" \| "warn" \| "error" }`：面板头角标 |
| 面板 → 驾驶舱 | `wm:open` | `{ v: 1, target: "item" \| "app" \| "seat", id }`：请求驾驶舱打开另一个面板 |
| 面板 → 驾驶舱 | `wm:ready` | `{ v: 1, supports: ["context", "select", "badge"] }`：声明支持的消息 |

规则：

1. 驾驶舱只接受来自自己嵌入的 iframe 的消息（核对 `event.source`），不按 origin 判断（沙箱 origin 是 `null`）。
2. 消息只带对象标识，不带业务数据正文；面板凭自己的台令牌去读数据。
3. 上下文字段词表在模板里声明；面板忽略不认识的字段。
4. `rev` 单调递增，面板丢弃旧的 `wm:context`。
