# 01 · 产品定义

> 阶段 0 草稿。业务场景与指标基线在私有台仓库，本文只写平台层。

## 一句话

**把一个分布在多台机器上的 agent 组织，收成一个人只需要「下达、决定、验收」的工作台。**

## 定位

系统由五个部件组成，各管一层：

| 层 | 部件 | 在产品里扮演什么 |
|---|---|---|
| 宿主 | DSH（DeepSeek Harness），加 tier-router 分档选模型 | 每个席位运行的地方 |
| 大脑 | superagent | 单个席位怎么接活：Source → Trigger → Eval（接不接）→ Mandate（授权）→ Ticket（工单）→ Report（六态）/ Attention；原则是尽量少占用人的注意力 |
| 总线 | dsh-open-a2a-net | 跨主机的身份（签名名片）、组队（canvas）、派活（route）、回执与对账 |
| 引擎 | ygl-trees | 证据、知识沉淀成技能、验证器、科技树；生命周期状态机以它的插件形态运行 |
| 入口 | **workbench-market（本仓）** | 人下达、审批、看产物；台、SOP、MCP、凭据库、身份 |

市场是**组织层**的人用入口；单个席位怎么干活，在 DSH 自己的 Web GUI 里看（见 [04](04-dsh-gui-relationship.md)）。

## 用户与角色

| 角色 | 主要任务 | 在市场里看什么 |
|---|---|---|
| 业务同事 | 提需求、回答 agent 的提问、验收产物 | 关注队列、事项时间线、台与产物 |
| 审核人 / 属主 | 授权、裁决、看全局 | 关注队列、驾驶舱、组织（席位与团队） |
| 席位操作者（运维、开发席） | 接入席位、排障、接管席位 | 组织、事件中心、连接向导；可深链进 DSH GUI |
| agent 席位 | 接活、执行、回报、提问 | 经 MCP 与 A2A 读写，不看界面 |
| 台作者 | 做台和 SOP | 市场、台仓库、设计标准 |

## 核心闭环

```
下达 ──▶ 事项 ──▶ 事件（A2A 投递）──▶ 席位接单（Eval）──▶ 执行（Ticket）
  ▲                                                            │
  │                        report / ask（进展、提问）◀──────────┤
  │                                                            ▼
沉淀（知识、技能、检查清单）◀── 人审（关注队列）◀── 回执 + 产物入台
```

每一步都落在「事项」这一个对象上（见 [02](02-concept-model.md)），人只在两处被打扰：agent 提问，和验收。

## 北极星与验收指标

- **北极星**：同类问题不再第二次找到属主（`repeat_to_owner → 0`）。
- **预演验收指标**（基线与目标值在私有仓）：
  - 人被打扰次数 / 事项；
  - 回执完整率（每个派出的事项都有终态回执）；
  - 端到端时长（下达 → 验收）；
  - 新接一个席位的耗时（目标不超过 10 分钟，靠连接向导）；
  - 故障定位时长（从出错到看到中文原因）。

## 对标：LobeHub 的概念在这里由谁承担

| LobeHub | 本产品 | 由哪个部件提供 |
|---|---|---|
| 助理 | 席位 | DSH 实例 + superagent + 名册（SOUL.md） |
| 助理档案 | 席位卡：模型档位、技能、MCP 授权、绑定的台、名额、在线状态 | A2A 名片与状态 + 系统清单 |
| @ 派给其他智能体 | 团队路由、总工分派 | A2A canvas 团队 + 路由席 |
| 任务 | 事项：事件 → 接单 → 工单 → 回执 | 市场 workbench-events → A2A → superagent Ticket |
| 自动批准 | 授权分档 | superagent Mandate + 协作规范档位 + MCP 授权 + 变更申请 |
| 工作区产物面板 | 台与产物 | 自产台、SOP 运行记录、文件 |
| 知识库、记忆 | 知识与常量 | ygl-trees 知识库与技能晋升 + 工作台变量与常量 |
| 定时任务 | 自动运维 | ygl-trees 的 job 与巡检 |
| 社区（带质量分级） | 市场：台、SOP、Skills、MCP | 品味规则 + 验证器分级 |

**我们有、它没有的**：证据链与独立验证器；跨主机信任（签名名片、OriginClaim）；回执对账账本；生命周期状态机；企业身份。

## 明确不做

- 不把对话框当唯一入口。业务同事不打字，他们审核；首页是「需要你注意的事」。
- 不给业务同事暴露模型选择器，展示席位能做什么就够了。
- 不做付费墙、不做开放社区。
- 不把市场改写成 DSH 插件（系统定义已裁定市场保持独立进程）。
- 不在市场里重新实现 A2A 协议（见 [07](07-a2a-adapter-refactor.md)）。
