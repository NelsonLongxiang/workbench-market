顺序上，一 → 二 → 三是主线；四可以和三并行（改的文件不同）；五、六依赖四；七与三错开，避免同时改 `index.ts`；八依赖六的留痕。被裁定挡住的阶段先跳过，做不被挡的。

## 三、执行规则

1. **一个阶段一次验收。** 阶段做完，逐条给出验收判据的结果：跑了什么命令、输出是什么、对应哪个提交。属主验收后，这个阶段才算完。
2. **PR 小而单一。** 搬路由时一次只搬一个域。PR 照现有流程走：实现方开，协同开发合并，高档改动要有非自我节点的评审。
3. **先红后绿。** 每个新检查、每条不变量都先给出会失败的样本，再给出通过的结果。安全面的 PR 照旧附对抗组。
4. **对外行为不变的阶段，用比对来证明。** 路由快照和录制回放必须零差异，不靠「看起来一样」。
5. **公开仓不写业务。** 涉及私有细节的，写在私有仓。
6. **生产部署不在本计划内。** 需要部署时，照旧由协同开发发部署单。
