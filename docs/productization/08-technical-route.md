# 08 · 技术路线收拢

> 阶段 0 草稿，2026-11-10 按属主当天的定调改写。01 ～ 07 定了产品是什么、和别的部件怎么接；这一篇定市场这个部件**怎么建**：每件事只有一个归属、一种做法。前提有两条：整套系统建在 Cordis 之上，不脱离；基础架构交付的是生长条件，不是功能。数字是 2026-11-10 在 main 上实测的，量法见 [09 的附录](09-constraint-system.md#附录量法)。

## 一、路线

市场是组织中心的入口（见 [10](10-boundary-and-norms.md)），只做四件事：

- **呈现**：驾驶舱、门户、自产台、SOP 执行页。
- **判定**：谁能做什么，哪些事要先问人。
- **留痕**：谁在什么时候、凭什么、做了什么。
- **索引**：事项指向各部件里的原件，市场不存第二份。

席位怎么运行、消息怎么送达、席位怎么判断、证据怎么存、业务规则是什么，都不归市场。市场消费这些部件的契约，不抄它们的实现。

怎么建，一句话：**把市场的 Cordis 化做完。** 现在只有数据访问在 Cordis 上下文里，其余都在外面。路由、判定、定时器、配置、扩展都用地基自带的构件来表达，不另造机制。

技术栈就下面这一套，阶段 1 ～ 2 不换也不加：

| 层 | 选定 | 备注 |
|---|---|---|
| 地基 | Cordis：插件、服务、依赖注入、事件、可撤销的注册、Config | 不另造插件机制 |
| 运行时与语言 | Node 24；TypeScript 直接运行，只用可擦除语法，server 没有构建步骤 | 类型检查在 CI 里单独跑 |
| HTTP | Express 4，单进程；由一个 HTTP 服务持有，路由由各域插件注册 | |
| 结构化数据 | SQLite（`node:sqlite`），一个库文件，是唯一的真源 | Redis 只放 SOP 进行中的热状态，可以不配；文件放数据目录和 LayerFS；凭据库是单独的加密文件 |
| 身份与权限 | 一层登录，由登录提供方插件负责（默认飞书）；主体、角色、授予自己管 | 见 [11](11-identity-and-permission.md) |
| 前端 | 一个应用：React 18 + antd 5 + Vite；token 由 `DESIGN.md` 生成 | |
| 入口面 | REST、MCP、门户代理、A2A 入站，只有这四个 | |
| 测试 | 零框架的 node 脚本；浏览器回归用 Playwright | |
| 交付形态 | 一个组织一个实例：单进程加一个数据目录 | 实例内部的隔离边界见 [租户边界评审件](../tenant-boundary-review.md) |

## 二、现状（实测）

| 关注点 | 今天 | 后果 |
|---|---|---|
| Cordis 化 | 上下文里只有 12 个服务，全是数据访问。152 条路由、守卫、6 个定时器、87 个配置读取点都在上下文之外；扩展挂载用的是自己的 `register(ctx)` 接口，不是 Cordis 插件 | 地基只用了一角：注册不能撤销，启动顺序靠手工排，新东西没有统一的口子可接 |
| 入口文件 | `server/src/index.ts` 5278 行，占 server 全部代码（72 个文件、16,994 行）的 31%；152 条路由有 139 条写在里面 | 改任何一处都要读全文件；并行的改动互相冲突 |
| 数据访问 | SQL 调用点 482 处：`services/` 187、`db.ts` 82、`index.ts` 81、另外 12 个文件 132 | 服务化（S1 → S3）做到一半：`services/` 和 `db.ts` 之外还有 213 处，分在 13 个文件 |
| 表结构 | 49 张表，其中 9 张定义在 `db.ts` 之外的 5 个文件；另有 2 处改表语句也在外面 | 想知道库里有什么，要翻 6 个文件 |
| 身份 | 实现写死在核心：4 个专属文件、409 行，被另外 8 个核心文件直接引用 | 换登录方式要改核心（见 [11](11-identity-and-permission.md)） |
| 判定 | `index.ts` 里 12 个守卫函数；另有十来个模块各自做准入或授权判定（登录门、URL 准入、内容准入、SOP 运行读授权、统一待办读授权、任务中心、A2A 入站等） | 「谁能做什么」没有一处能整体读出来 |
| 留痕 | 名字像留痕的表 10 张，各有各的写法 | 没有统一的写入口，也没有统一的查看面 |
| 等人拍板 | 5 处：变更申请、MCP 权限申请、工作台事件的 `ask`、任务中心收件、待属主看板 | 统一待办只汇总了其中 2 处 |
| 出站投递 | 4 条路径、2 套重试（见 [07](07-a2a-adapter-refactor.md)） | 同一个修复要改两处 |
| 周期任务 | 6 个 `setInterval`，分在 5 个文件 | 没有清单；哪个停了没人知道 |
| 配置 | 46 个环境变量名、87 个读取点、17 个文件；仓库里核对「环境变量是否都写进 README」的脚本今天是红的（1 个没写） | 没有集中校验的地方 |
| 类型 | server 从没做过类型检查（CI 只查 web 的类型和 server 的语法）。临时跑一次：宽松模式 85 个错误，严格模式 426 个 | 85 个里有真缺陷：一处失败分支在声明之前引用了变量，靠外层的错误处理兜住，行为碰巧没变 |
| 测试 | 测试类脚本 176 个，93 个在 CI。不在 CI 的 83 个里：8 个有 package.json 命令，10 个由本地验证器的流水线调用，7 个被别的脚本调用，58 个没有任何执行入口 | 写了不跑的测试，不提供保护 |
| 前端取数 | 约定的入口是 `web/src/api.ts`；它之外还有 33 处直接 `fetch`，分在 13 个文件 | 鉴权头和错误处理各写各的 |

这些数字不是哪一次改动造成的。每个 PR 单看都对，加起来路线就散了——所以收拢之后还要有东西守住它，见 [09](09-constraint-system.md)。

## 三、收拢后的形态

```
调用方      人（浏览器）     agent 席位     台页面（沙箱）     外部节点
                │               │                │                │
面          ┌───┴───────────────┴────────────────┴────────────────┴───┐
            │    REST         MCP         门户代理        A2A 入站     │   面是插件，路由是可撤销的注册
            └──────────────────────────┬──────────────────────────────┘
入口三步              身份  ──→  判定  ──→  留痕                           服务与事件，全站各只有一处
                                       │
领域插件     workbench · app · sop · skill · mcp · vars · 事项 …           各带自己的服务、路由、定时器
                                       │
存储与外接   SQLite │ 文件 │ 外部节点插件（A2A）│ ygl-trees 上游 │ DSH 深链
```

- 这些都在同一个 Cordis 上下文里。领域插件声明自己依赖哪些服务，上下文等依赖就绪再启动它。
- 请求只有一条路：从面进，过入口三步，到领域插件。领域插件不认识 HTTP 的细节，外接的插件不认识业务。
- `index.ts` 最后只做一件事：建上下文，按配置把插件装起来。
- 界面同理：一个应用、一套 token、一个取数入口。

## 五、入口的三步：身份 → 判定 → 留痕

四个入口面今天各有各的身份识别和权限判断。收拢成三步，每一步全站只有一处，都用 Cordis 的构件：

| 步 | 构件 | 只回答 |
|---|---|---|
| 身份 | 服务。实现在登录提供方插件和席位凭据里 | 这是谁 |
| 判定 | 事件。策略是监听它的插件，有权拦下 | 这个主体能不能做这件事 |
| 留痕 | 服务。一张只增不改的总账 | 记下来：谁、凭什么、做了什么、结果 |

```ts
type Principal = {
  id: string;        // user:<名>、seat:<名>、app:<slug>、system:<名>、node:<团队>
  kind: 'human' | 'seat' | 'app' | 'system' | 'node';
  via: { provider: string; subject: string }; // 这次请求凭的是哪个外部身份
  verified: boolean; // 没绑定的来源只当数据，不触发动作
};

type Decision = {
  effect: 'allow' | 'ask' | 'deny';
  rule: string;      // 命中的规则，留痕和排障都用它
  reason: string;    // 给人看的一句话
  grant?: string;    // 命中的授予
};
```

领域插件声明依赖，注册路由时把动作报上来（示意）：

```ts
export const name = 'app-data';
export const inject = ['http', 'permission', 'audit'];

export function apply(ctx) {
  ctx.http.route(
    { method: 'post', path: '/api/apps/:slug/data', access: 'app', action: 'app-data.submit' },
    handler,
  );
}
```

没声明访问类别和动作的路由注册不上。插件卸载时，它注册的路由、监听器、定时器一并撤销。主体、角色、授予和判定的顺序见 [11](11-identity-and-permission.md)。

收拢换来三样东西：

- **「谁能做什么」能整张读出来。** 动作由插件声明，授予在一张表里，不是散在二十来个地方的 `if`。
- **「先问人」成为通用结果。** 变更申请、MCP 权限申请今天就是这个形状——请求落成一条待决，批准后生效。收拢之后任何动作都能配置成先问人，问题自动进「关注」。[06](06-a2a-superagent-fusion.md) 里 held、observe、auto 的逐步放权，开关就落在这里。
- **留痕不靠自觉。** 写操作只能经注册过的路由进来，经过了就一定有记录。

为什么这三步必须各只有一处：管理者要的可控就是三个问题——谁在干、凭什么、什么在等我。答案如果是从多处拼出来的，拼的地方越多越不可信。

## 六、不做清单

阶段 1 ～ 2 有效。产品层面的不做见 [01](01-product-definition.md)，这里只列构建上的：

1. 不自造插件机制。扩展、路由、定时器、配置都用 Cordis 的构件。
2. 不引入第二个数据库、ORM 或迁移框架。
3. 不引入工作流引擎。流程的载体是 SOP。
4. 不拆微服务，不做一库多租户。**一个组织一个实例**，多个组织就是多个实例。
5. 不引入第二个前端框架、组件库或状态库。
6. 不自建 agent 运行时、消息总线、知识库。
7. 不自建登录：不存密码，不做登录页。用户、角色、权限自己管（[11](11-identity-and-permission.md)）。
8. 市场进程不新增模型调用。
9. 不换测试框架，不给 server 加构建步骤。
10. 公开仓不放业务。

要破例，就改这张清单：PR 里看得见，由属主裁定。

## 七、顺序

| 序 | 做什么 | 性质 | 前置 |
|---|---|---|---|
| 0 | 约束先行：路线清单、体检脚本（只报告）、基线、仓库根 `AGENTS.md`（见 [09](09-constraint-system.md)） | 不改运行时 | 属主裁定红线范围 |
| 1 | 建 HTTP 服务；按域把路由和守卫搬进领域插件 | 纯移动，对外行为不变 | 0 |
| 2 | 身份做成服务，现有实现包成登录提供方插件（[11](11-identity-and-permission.md) 过渡第 1 ～ 2 步） | 对外行为不变 | 1 |
| 3 | A2A 以外部节点插件接入，唯一 outbox（[07](07-a2a-adapter-refactor.md)） | 对外行为不变 | 与 1 错开，避免同时改 `index.ts` |
| 4 | 主体、角色、授予、判定、留痕（[11](11-identity-and-permission.md) 过渡第 3 ～ 6 步） | 先并行比对，零差异后切换 | 2 |
| 5 | 事项表、事项日志、「关注」读模型 | 新增 | 4 的留痕 |
| 持续 | 定时器改用 Cordis 的定时器服务，配置改成插件 Config，类型错误清零 | 随手收 | 0 |

界面线与此并行：Token v2 → 驾驶舱 v2 外壳 → 体验版面板（[05](05-token-v2.md)、[03](03-cockpit-v2.md)）。

- **终点**：`index.ts` 只做装配，0 条路由、0 处 SQL；所有注册都在插件里。每个阶段收到哪，在约束的预算档打开时按当时的基线定。
- **对阶段 1 的影响**：这条线给「真实底座」加了第 1、2、4 三步，体验版不依赖它们。工期紧时先保 0、1、3、5；第 4 步可以只做到并行比对，切换留到预演之后。

风险：

- **路由顺序**：Express 按注册顺序匹配，搬动会改变顺序。路由清单的快照带顺序，搬前搬后必须一致，再加录制回放。
- **并行冲突**：多个 PR 同时改 `index.ts`。一次只搬一个域，PR 要小，搬的那个域当天不接别的改动。
- **判定改错权限**：不重写判定逻辑，只换调用位置；并行比对零差异才切换；安全面 PR 照旧附对抗组。
- **扩展接口换代**：私有扩展要跟着改。旧接口保留一版，两种写法并存期间行为一致。
