# 10 · 边界与规范（去中心化的网络，中心化的核心）

> 阶段 0 草稿。回答一个问题：A2A 是去中心化的 agent 网络，核心部件却是中心化构建的，边界划在哪、跨边界守什么规矩。前提是一个事实（属主 2026-11-10）：整套系统建在 Cordis 之上，不脱离。总原则与七条规范待属主确认。

## 一、结论

边界只有一条：**上下文的边**。域内中心化，域间去中心化。

- **域**是一个 Cordis 上下文，也就是一个进程：一个席位所在的宿主是一个域，组织的中心是一个域。
- **域内**由上下文统管：服务按名字取用，插件声明依赖，判定走事件，注册可以撤销。这是中心化的，也应该是。
- **域间**没有共同的上下文，只有消息：CLI、MCP、HTTP、A2A。
- A2A 网络自己也是这样造的：每个节点的上下文里各装一个网络插件，合起来才显得去中心化。

所以去中心化不是另一种架构，而是「没有上下文的上下文」——不存在一个统管所有节点的根。矛盾只在三种情况下出现：一个域的真相被别的域直接写；指望网络替大家保存共同的真相；中心把自己插进域与域之间当中转。

## 二、为什么：Cordis 的保证到哪为止

Cordis 在一个上下文之内给四样保证。出了上下文，这四样都没有了；跨域的规范，就是把它们在网络上补回来。

| Cordis 在域内给的 | 出了上下文，用什么补 |
|---|---|
| 服务按名字注入，依赖等就绪再启动 | 名片发现，加契约版本。对端不在记「未知」，不记失败 |
| 注册是可撤销的副作用，插件卸载时一并撤销 | 每个跨域请求带 id 和幂等键，必须以回执收尾；没收尾的记在账本上 |
| 判定走事件，策略监听器有权拦下 | 每个域自己判。对端的结论进域只是输入，要过入口再判一次 |
| 上下文是服务的唯一容器 | 每个域只写自己的真相；别人的真相只存 id |

## 三、三层，以及东西放哪

判别法只有一句：**答案要对几方一致，就放在哪一层。**

| 层 | 谁是主 | 放什么 | 例子 |
|---|---|---|---|
| 席位本地 | 席位自己的上下文 | 一方自己知道就行的 | 会话、草稿、接不接单的判断、本地任务账本 |
| 网络 | 没有主，当事双方各记一份 | 两方对得上就行的 | 派发、回执、协作消息、成员关系 |
| 组织中心 | 中心的上下文，一个组织一个 | 全组织只能有一个答案的 | 主体、授权、声明的规则、事实账本、人的决定 |

和「生长环境」的关系：基础架构为业务提供生长条件，生长点也分两种。域内的生长点是插件接缝，域间的生长点是面和它的契约。新东西从哪种口子长出来，就守哪种规矩。

## 四、面与入口

- **面**：把一个域里的服务暴露到域外的插件，形态是 CLI、MCP、HTTP 或 A2A。跨域的一切往来只发生在面与面之间。
- **入口**：组织中心的面。它在面的职责之上多做三步——身份、判定、留痕（见 [08](08-technical-route.md) 与 [11](11-identity-and-permission.md)）。凡是要改组织的东西，只能从入口进。

| 谁要进来 | 走哪个入口 | 现状 |
|---|---|---|
| 人 | 页面；即时通讯里的审批卡片 | 页面已有；卡片未做 |
| 席位 | MCP 网关（待确认） | 网关已有，但席位在这里的身份和它的网络身份互不相认 |
| 外部节点 | A2A 入站 | 已有，按绑定准入 |
| 系统作业、规则 | 本机 | 已有 |

入口在 Cordis 里不是特殊的东西：它就是组织中心那个上下文里的几个插件。别的域注入不到中心的服务，所以只能过入口；这道限制是地基自带的，不靠约定。

## 五、七条规范

| # | 规范 | 怎么查 |
|---|---|---|
| 1 | **一个上下文一个主。** 每个域只写自己的真相 | 库文件和数据目录只被一个进程打开；别的部件里只出现对方的 id |
| 2 | **跨域只走面。** 不共享库文件，不共享目录，不复制对方代码。要用对方的能力，要么以插件装进自己的上下文，要么经对方的面调 | 只引用对方包的公开导出；[09](09-constraint-system.md) 的分层检查 |
| 3 | **网络身份只证明来源。** 权限只来自中心的绑定；没绑定的只当数据 | 对抗样本：未绑定的来源发来的消息不触发任何动作 |
| 4 | **中心不审批「做事」，只守「改组织的东西」。** 做事照协作规范，自主决定；改组织的东西只走入口，按写明的声明放行——规则能判的自动放，声明要人批的才找人 | 入口上每个写动作都有声明的放行方式；没有声明的写动作一律拒绝 |
| 5 | **网络里传的都是说法，中心只认证据和人的决定。** 回执结清的是派发的欠账，不是业务状态 | 对抗样本：伪造一条「已完成」的回执，业务状态不变 |
| 6 | **中心在网络里只是一个普通节点。** 协议上没有特权，不做中转，席位之间直连；别的组织可以有自己的中心 | 网络插件不依赖中心；中心没有转发端点 |
| 7 | **故障各自独立。** 中心停了，活照干，组织的东西改不了，回报在节点侧排队；节点失联，记未知，不盲目重发 | 停机演练：恢复后回报按幂等键重放，不重复、不丢 |

第 4 条不是把「先授权」加回来。协作规范取消了事前授权，限制只认两处：项目写明的红线、派活方的完成标准。组织的红线同样要写明——写在中心的声明里，入口照着执行，不临时加批。两边的回避原则也是同一条：评审的不能是作者，审批的不能是提议人。

## 六、现状里要收的

- **市场只 Cordis 化了一半。** 数据服务在上下文里；路由、守卫、定时器、配置在外面；扩展挂载用的是自己的接口，不是 Cordis 插件（见 [08](08-technical-route.md)）。
- **网络能力是按函数引用的。** 网络插件要求宿主提供 agent 会话才有的服务，不跑 agent 的宿主装不上。缺一个「外部节点」形态的插件；[07](07-a2a-adapter-refactor.md) 提议的工具包应当做成它。
- **席位的身份是散的。** 网络句柄、A2A 绑定、MCP 会话各记各的（见 [11](11-identity-and-permission.md)）。
- **身份的实现写死在核心里。** 应当是接缝后面的一个插件（见 [11](11-identity-and-permission.md)）。

## 待决

- **P1**：总原则——域内中心化、域间去中心化；中心不做中转；核心不改成分布式。
- **P1**：席位进中心的入口放在市场的 MCP 网关。
- P2：七条规范的检查各落在 [09](09-constraint-system.md) 的哪一批。
