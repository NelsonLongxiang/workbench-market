## 三、数据怎么存

任务存成台里一个普通数据集，一行一个节点；依赖写在节点自己那一行，不另建边表。

| 列（名字由视图描述指定） | 类型 | 用途 |
|---|---|---|
| 编号 | text 或 integer，主键 | 节点 id，最长 64 字 |
| 名称 | text | 节点上的字 |
| 依赖 | text | 前置，写法见下 |
| 角色 | text（`dag`、`flow` 必须指定这一列；每行可空） | `start` 起点、`end` 主线终点、`branch_end` 支线终点，其余留空 |
| 状态 | text | 如 `todo`、`doing`、`done`、`failed`；哪些值算完成由 `done_values` 定 |
| 进度 | 数值（可选） | 0～100 |
| 来源 | text（可选） | 采集来源：科技树节点键、工单号、链接（只认 http(s)） |
| 负责人、分组、开始、截止等 | 任意（可选） | 详情、泳道、甘特图 |

**依赖写法**（逗号分隔，每格最多 50 项）：

- `a`：必需前置（缺省）。所有必需前置完成，本节点才「可开始」。
- `?a`：可选前置。画虚线，不挡开始。
- `a|b`：任一前置，组里有一个完成就算满足。
- `a=说法`（或 `?a=说法`）：流程图边上的字，如判断分支的「是」「否」。
- 编号里不能有逗号、等号、竖线、问号；自己指自己的项忽略并提示。

为什么依赖放在同一行：AI 一次 `dataset_upsert` 就同时改完节点和它的依赖，不会出现「节点写了、边没写」的半截状态。

**数据来源（D3）**：ygl-trees 的科技树、A2A 工单、PR 等只是 AI 采集的来源，市场不新增读它们的路径。AI 采集后经 MCP 写进台的数据集，来源留在来源列。

甘特图另要 **开始**、**截止**（date 或 datetime）两列；流程图另可给 **形状** 列（`step`、`decision`；起点、终点由角色列定）。进度随时间的变化由 AI 往另一个数据集 `dataset_append`（时间、完成数、总数），用现有 line、progress、stat 画。

## 三之二、轻量版 trees（D8）

借 ygl-trees 科技树模型（技能 `ygl-trees-techtree`）里轻的部分：

| 借什么 | ygl-trees 里 | 任务图里 |
|---|---|---|
| 唯一事实源与派生索引 | `node_edges` 邻接表是唯一事实源，闭包与拓扑层是派生 | 依赖列是唯一事实源；层号、祖先、后代在渲染时现算，不另存 |
| 边的强弱 | 必检边、`--optional` 可选、`--mode OR` 任一 | `a` 必需、`?a` 可选、`a\|b` 任一 |
| 可开始集合 | `node ready`；`node can` 分列缺的必检与可选 | 派生状态「可开始」「等前置」；详情分列缺的必需前置、缺的可选前置 |
| 到目标的路径 | `node path`（解锁顺序，目标恒最后） | 点终点：高亮它的必需前置闭包；摘要「到主线终点还差 N 个」 |
| 解锁后挂证据 | lifecycle「解锁后必挂证据」 | 给了 `source_col` 时，已完成却没留来源的节点计数提示（不拦） |

**不借**：互斥（excludes）、XOR、NOT；条件门槛与 eval 判定；成本；多上下文状态袋；写入时的环守卫（T7 在渲染时核）。AI 写的是任务进度，不是解锁规则；重的部分需要时进第 2 步。

**完成怎么认**：`done_values`（缺省 `["done"]`）列出算完成的状态值。派生状态不改写状态列（状态列仍归 AI 写）；两者矛盾时（状态写着进行中、必需前置却没完成）只提示「提前开工」，不报错。

## 四、`dag` 的契约

| 键 | 必填 | 说明 |
|---|---|---|
| `type`、`title`、`span` | type | 同其它组件 |
| `query` | 是 | 查任务数据集；明细查询（不能有 group、measures），**不能写 limit、offset**（第五节之一） |
| `id_col`、`label_col` | 是 | 编号列、名称列 |
| `deps_col` | 是 | 依赖列（text） |
| `role_col` | 是 | 角色列（text） |
| `status_col`、`done_values` | 否 | 状态列与算完成的值；说法和色调照 `value_labels`（success / warning / danger / default） |
| `progress_col` | 否 | 进度列（数值列） |
| `source_col` | 否 | 来源列 |
| `group_col` | 否 | 按组分泳道 |
| `detail_cols` | 否 | 点开节点时显示的列，1～12 个 |
| `direction` | 否 | `LR`（缺省）或 `TB` |
| `value_labels`、`column_labels` | 否 | 同 table |

保存校验（`view_put` 与页面保存同一处）：列都存在、类型对、明细查询、没写 limit 与 offset。
契约交付：`BLOCK_CONTRACT` 加类型的同时，在 `BLOCK_BRANCH_PROPS` 加每个键的字段说明，跑 `gen-view-doc-schema.mjs` 重生成技能里的 schema，契约测试照常过；`view_put` 工具定义仍只留最小形状。

## 四之二、`gantt` 与 `flow` 的契约

**`gantt`**：`query`、`id_col`、`label_col`、`start_col`、`end_col` 必填；`deps_col`、`role_col`、`status_col`、`done_values`、`progress_col`、`group_col`、`detail_cols`、`value_labels`、`column_labels` 可选。开始、截止两列在数据集定义里必须是必填列（`required: true`），保存视图时核，写入为空即被拒（server/src/services/bench-store-core.ts:306）。每个任务一条横条；进度画成条内填充；给了依赖就画箭头（前置的截止 → 后继的开始）；有「今天」竖线；截止已过没完成的条用 danger 色调；给了角色列就在终点、支线终点的条尾画标记。

**`flow`**：键同 `dag`，另加 `shape_col`。与 `dag` 的不同：允许循环（如「审核不过 → 退回修改」），回边画成弯线；节点按形状画（起点终点圆角、判断菱形、步骤矩形）；边上可以有字。

三种组件的查询都不能写 limit、offset。

## 五、渲染

### 五之一、输入范围：先定看的是哪些任务

- 图块取数**不分页**：服务端按块的查询取最多 501 行（T3 的 500 加 1，用来判截断）。
- **全量**：查询没有任何筛选条件（静态条件和 `$参数` 都没有），也没有截断。
- **部分**：有筛选或截断。部分结果里：
  - 指向结果之外的依赖画成灰色「范围外：X」占位，**不说成不存在**；
  - 不核起点终点、支线终点、走得到走不到，不算完成率（否则会把被筛掉后继的节点当成叶子）；
  - 顶部说明「当前是部分任务（筛选了 / 超过 500 个只画了前 500 个），终点核对和完成率只在看全部任务时做」，截断时写明实际画出的个数。
- 上限：节点 500；每格依赖 50 项（超出截掉并提示）；边 5000；占位节点 100（超出合并成「另有 N 个」）；编号 64 字。

### 五之二、核对顺序

1. **解析**：按逗号切开、去空白、去重；自依赖去掉并提示；写法不合的项列为「看不懂的依赖」。
2. **范围**：按五之一判全量或部分。
3. **环**：`dag` 有环（只算必需和任一边）就整块报「依赖有环：A → B → A」，列出一条环，不画图；`flow` 求强连通分量，含回边的分量照画。
4. **依赖找不到**：全量时画灰色「缺失：X」占位并在顶部计数；部分时按五之一画「范围外」。
5. **起点终点（D5，仅全量）**：`start`、`end` 各恰好一个；起点不能有前置。不对就顶部报错、摘要标红、不算完成率，图照画。
6. **支线终点与走得到（D6，仅全量）**：
   - 没有后继的节点必须标 `end` 或 `branch_end`，否则报「支线没确认终点」，把这条支线（往回到与其它线分叉处）标红；
   - 每个节点顺后继都要能走到某个 `end` 或 `branch_end`，走不到的标红（这条覆盖 `flow` 里没有出口的循环）；
   - 从起点要能走到每个节点，走不到的标出来；
   - 支线汇合回主线的，不需要支线终点。
7. **派生状态**：已完成 / 可开始 / 等前置（详情分列缺的必需、缺的可选前置）；矛盾时提示「提前开工」。
8. **摘要**（五之三）。
9. **布局**：分层，纯 TypeScript，放在 `blocks-view.ts`。`flow` 先把强连通分量缩成一点再分层；层号 = 最长必需前置链；层内一到两遍重心法减交叉；给了分组就先分泳道。
10. **画法**：`dag`、`flow` 用 ECharts graph（多注册 `GraphChart`，`layout: 'none'`，坐标用第 9 步）；`gantt` 用 ECharts custom 系列。颜色、字号只用 token。

除 `dag` 有环外，报错都不挡画图。

### 五之三、摘要口径

- 计数（共、完成、可开始、等前置、出错）按**画出来的**节点算。
- 完成率只在全量且第 5 步通过时算：主线终点的必需前置闭包（含终点）里已完成的占比；任一组算一个，组里有一个完成就算完成。
- 「到主线终点还差 N 个」按同一闭包里未完成的算；各支线终点单列完成情况。

### 五之四、交互与等价表格

- 缩放、平移；点节点在侧栏看详情；悬停高亮前置和后继链；点终点高亮到它的路径。
- 组件右上角切到等价表格（名称、状态、派生状态、进度、前置、后继、角色），照 docs/data-views.md「图表都有等价的表格视图」。表格可用 Tab 与方向键遍历，读屏可读；图上的节点也可用 Tab 依次聚焦、回车打开详情。
- 空结果显示「还没有任务」；块报错（取数失败、校验失败）照现有组件的四种状态显示原因，不显示成没有数据。

### 五之五、动态改写

改起点、终点、支线终点就是 upsert 改角色列。台库写入有事务（`BEGIN IMMEDIATE`，server/src/services/bench-store-core.ts:159），实现时核对一次 upsert 的多行在同一事务里，「撤旧终点、标新终点」不露中间态；页面经实时刷新 5 秒内重画。

不做：拖拽、在图上改数据、自动推算关键路径（第 2 步候选）。

### 五之六、实时刷新（D2）

1. 新路由 `GET /api/bench-views/:bench/changes?view=…`，回一个游标：**和取数修订同一组维度**——`bs_writes`、`bs_changes` 的最大编号与数据集定义（server/src/services/bench-store-core.ts:911–915），再加视图当前启用的版本。普通 upsert（包括改角色列）推进 `bs_writes`，所以会被看到。
2. 取数（render）的回应里带同一个游标，在同一个排队槽里算；页面拿它和 `/changes` 的回答比，不一样才重新取数。
3. 路由顺序照取数路由：`allowActor(render)` 判权在任何台库读取之前 → 台没登记判过权才 404 → 取游标 → `assertBenchBinding` 之后同步回应，中间不再 await。不新增动作，沿用 `bench-store.render` 声明，进路由快照与回放。
4. 页面可见时每 5 秒问一次；不可见就停，回来立刻问一次。重新取数期间旧图照常显示；状态或进度变了的节点短暂高亮。
5. 所有组件都受益（表格、统计卡也跟着刷新），驾驶舱面板同样接入。

不推送（SSE、WebSocket）：要长连接、代理配置和连接数上限，第 1 步不值。

## 六、AI 怎么用（示例）

1. `dataset_define` 一个 `tasks` 数据集：`id`（主键）、`name`、`deps`、`role`、`status`、`progress`、`source`、`owner`、`due`。
2. 写起点、终点（`role`），拆出的任务 upsert 新行并填 `deps`（如 `design,?research,impl_a|impl_b`）；支线要写 `branch_end`。
3. 每推进一步 upsert 改 `status`、`progress`，往 `progress_log` `dataset_append` 一行。
4. `view_put`：顶上 stat（完成率）、中间 `dag`、下面 line（`progress_log`）。

技能 `skills/wm-data-views` 在本仓，`references/views.md` 补三种组件写法、依赖写法与这个示例。
