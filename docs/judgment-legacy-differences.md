# 存量差异清单（判定切换前登记）

给属主看的。阶段六要把「谁能做什么」从散在各处的守卫，换成统一的判定。换的时候有一条原则：

> 切换本身对外零差异，不借切换顺手放宽或收紧任何东西。

所以统一判定照着今天的行为登记了几条明确的规则和例外。下面这些是今天的行为里看起来不合理、但这次**照原样保留**的地方。每一条以后单独立项、单独改，改之前在这里写清楚。

比对的口径：
- 比对打开时，跑全部录制回放和 CI 里的脚本，新旧结论不一致为 0；
- 每种身份（匿名、本机页面、本机命令行、员工、身份来源的管理员、管理口令）把每条 GET 打一遍、写面挑代表，不一致也为 0（`scripts/judgment-compare-sweep-test.mjs`）；
- 「不确定」「状态码不代表授权」「被完整性门拦下」三类各自计数，都能对上下面的登记。

## A2 本机命令行：同一个身份，有的管理面认、有的不认

**现状**：在服务器本机直接调接口、不带管理口令、也不是浏览器的请求（「本机命令行」）。
- 能做的：
  - 过写请求的总门：普通的写，比如登记台、改类型、驾驶舱、Cookie 池、设置，自产台的同步、切版本和删除（任务中心元台除外）；
  - 主体管理和授予管理：本机命令行在这里还算属主，能放行管理员级的授予；
  - 还没设过管理口令时，首次设置口令；
  - 自产台的匿名提交面（提交数据、上传文件）和数据、文件的读取，和匿名一样；
  - SOP run 的开建、保存一步、完成、指派、附件，和升级（升级只限管理员或本机命令行）。
- 不能做的（要带口令）：A2A 绑定、变更申请、门户观测状态、导出真值、技能的发布与安装、任务中心的写、改或清管理口令、任务中心这个 SOP 台的发布与下架、任务中心元台的切版本和删除、MCP 网关的管理面。

**风险**：低。只限能登上服务器的人，这些人本来就能直接改库。问题在口径不一致：同样一条脚本，换一个接口就要口令，容易误会。

**建议**：定一个口径，二选一：
- 本机命令行一律按属主算（要属主拍板）；
- 本机命令行一律要口令（主体与授予管理面也改成要口令）。

**统一判定里怎么登记的**：内置身份「本机命令行」，能做的动作逐条列出（`server/src/judgment-builtins.ts`，也在 `surfaces/actions.json` 的 builtins 里）。没列的照旧拒。

## C 匿名：登录门关着时开放的读面

**现状**：登录门关着的部署里（`WM_LOGIN_GATE` 不是 `enforce`），不登录也能读这些：
- 类型、台列表与单个台、自产台列表与单台、驾驶舱列表与详情、统计、总览、「我是不是管理员」的探测；
- Cookie 池列表（值已遮）、设置（上游凭据已遮）；
- 技能列表与角色包、SOP 列表与时间线、任务中心列表、策略与模板；
- 导出（掩码的，取真值要管理员）、管理口令的状态；
- A2A 签名卡片、设计 token、关注（不登录看到的是空的）、SSO 回调；
- 自产台的匿名提交面：提交数据、上传文件（不经写请求总门），和台的数据、文件的读取；
- SOP run 的开建、保存一步、完成、附件（不经写请求总门，附件另按 run 的凭据判），run 列表和读（没有读授权只回元数据）。

登录门开着时，匿名在进到这些路由之前就被挡住了，不受这一条影响。

**风险**：中。登录门关着时，内部的清单（有哪些台、哪些技能、哪些 SOP）对能访问到这个地址的人都可读。

**建议**：
- 生产一律开登录门；
- 或者给匿名定一份最小清单（A2A 卡片、设计 token、SSO 回调、健康检查），其余收进「成员」。

**统一判定里怎么登记的**：内置身份「匿名」，开放的读面和匿名提交面逐条列出（`ANONYMOUS_ACTIONS`）。另有两处由它推出来，不另抄：
- 本机页面（回环直连的同源浏览器）：匿名能做的它都能做，再加下面的例外；
- 匿名的底：登录认出来的人判不过时，匿名今天能做的照样允许——今天匿名能做的，登录的人当然也能做（比如员工往台里提交数据、开建 run）。
  迁移只给员工 `member`（只有读），不靠这一条的话，切换之后员工反而做不了匿名能做的写。

### C 的例外：本机页面首次设置管理口令

**现状**：还没设过管理口令时，在服务器本机打开的页面（同源）可以首次设置口令；设过之后要带当前口令才能改。

**风险**：低。只在没有口令时、只限本机同源页面。

**建议**：保持；或者改成只许本机命令行首次设置。

**统一判定里怎么登记的**：内置身份「本机页面」，加上细分出来的动作 `admin-token.first-set`（只在还没设过口令时成立，在请求进来时判）。

## D 管理口令做决定

**现状**：带管理口令的请求能批准或驳回变更申请，能批准或驳回 MCP 的访问申请，能答复「关注」里的提问。这些在设计里是「决定类」，按规则只认人：不是人的身份做决定，应该转成提议、先问人。

**风险**：中。管理口令是共享的，决定落不到具体的人；事后看留痕，只知道是「拿口令的人」。

**建议**：
- 收紧为只认人：管理口令保留应急用途，但决定类改走「先问人」；
- 或者明确口令持有人就是属主的代理，并要求每次决定写理由。

**统一判定里怎么登记的**：内置身份「管理口令」照管理员角色算，另把这五个决定类动作登记为「代属主行事」（`attention.answer`、`change-request.approve`、`change-request.reject`、`mcp.access-approve`、`mcp.access-reject`）。判定的留痕里标明经口令。主体表里不是人的主体（席位等）做决定，照旧转提议，不受这条例外影响。

## E 门户观测状态只认管理口令

**现状**：`GET /api/content/observation` 只认管理口令；身份来源说是管理员的人、本机命令行都读不到。和别的管理读面（管理口令或身份来源的管理员都认）口径不一样。

**风险**：低。只是口径不一致，没有放宽。

**建议**：和别的管理读面一致，改成管理员都认；或者说明为什么只认口令。

**统一判定里怎么登记的**：收窄（`NARROWED`）：这个动作只有管理口令能做。否则迁移出来的 `admin` 会让它在切换时放宽。

## 不算存量差异、但要知道的两类登记

### 状态码不代表授权

这些路由回的 401、403 不是「谁能做什么」的结论，是各自领域的判断。它们留在各域自己的处理逻辑里，不并进统一判定。比对时这些路由不拿状态码比，单列计数。

| 路由 | 原因 |
|---|---|
| 登记、修改台 | 地址不许登记时回 403，是登记规则 |
| 导入 | 导入的行里有不许登记的地址时回 403 |
| 「你是谁」 | 没登录 401、门户账号 403，是认人的结果 |
| 登录方式的失效通知 | 签名、来源不对回 401，由登录方式插件判 |
| 登录回调 | 外人、别的租户回 403，是登录方式的结论 |
| SOP 定义 | 草稿、已下架的只给管理员看 |
| SOP 执行页 | 已下架的回 403 |
| 从仓库同步台 | 任务中心元台不从仓库同步，回 403，是台的规则 |
| SOP run 的附件（列出、下载、上传、引用）、升级预检、保存一步和完成 | 按 run 的凭据（读能力、上传令牌、对源 run 的读授权）判，是 run 授权的结论；以后按对象范围的授予接进判定 |
| MCP 内嵌的 REST（`/api/mcp-rest/*`、`/openapi.json`） | 只认网关的 MCP 会话令牌和工具授权，是会话的结论，不是登录身份的 |
| 台数据与附件的读（列数据、列附件、下载附件） | 按台令牌或管理员判：带台令牌的匿名也能读，403 不是登录身份的结论；本机命令行照旧列在内置清单里 |
| 事项席位消息的已读与回复 | 按事项的建立人判（建立人本人或管理员），是事项上的规则；以后按对象范围的授予接进判定 |

每一条写在路由注册的地方（`statusNotVerdict`），也在 `surfaces/actions.json` 里。

### 完整性门

跨站、别的站来源的请求，带着有效口令也会被拒（同源门）。这是请求完整性的门，不是身份授权：
- 它在统一判定之外、之前，切换时原样保留；
- 比对时，被它拦下的请求不比，单列计数。

有一例对抗专门证明它没有因为有了判定而变成摆设：把同源门去掉，现有测试会变红。

### 收窄：比角色更严的动作

少数动作今天比管理员的口径更严，判定里照样表达出来（`server/src/judgment-builtins.ts` 的 `NARROWED`，也在 `surfaces/actions.json` 的 `builtins.narrowed` 里）。列的身份之外，哪怕有覆盖它的授予、照管理员角色算，也拒绝：

| 动作 | 只有谁能做 | 原因 |
|---|---|---|
| 门户观测状态 `content.observation` | 管理口令 | 见 E |
| 整批撤销迁移出来的授予 `grant.revoke-migration` | 属主、本机命令行 | 处理函数要求属主，比管理员严。这是授予管理面本身的规则，不是存量差异 |

### 按请求细分的动作

同一条路由上，有几种请求今天的要求不一样。登记成细分的动作，不用模糊的宽映射：

| 路由 | 细分 | 原因 |
|---|---|---|
| 导出 | 带 `reveal=1` 的是 `market.export-reveal`（管理类），不带的是 `market.export`（读） | 掩码导出今天谁都能拿，取真值要管理员 |
| SOP 发布、下架 | 任务中心这个台是 `sop.publish-task-center` / `sop.deprecate-task-center` | 只有这个台的发布、下架要管理员，别的只过写请求总门 |
| 台切版本、删台 | 任务中心元台是 `app.rollback-task-center` / `app.delete-task-center` | 只有这个台要管理员，别的只过写请求总门 |
| 设置管理口令 | 还没设过时是 `admin-token.first-set` | 首次设置的规则和修改不一样 |
