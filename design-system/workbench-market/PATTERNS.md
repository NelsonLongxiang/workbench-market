# 工作台信息架构与页面模式（v1.0.0）

token 取值见仓库根 [`DESIGN.md`](../../DESIGN.md)。本文件规定**菜单与目录、页面骨架、四类核心页面**怎么搭。与 DESIGN.md 一样只写规范、CI 不拦。

## 1. 现状问题

| 问题 | 位置 |
|---|---|
| 菜单 10 项平铺，日常使用页和管理页混在一起；「统一待办」「技能市场」用了同一个图标 | `web/src/App.tsx` |
| 页面骨架不一：11 个页面里 6 个用 `PageContainer`，其余直接 `Card` 或什么都不包 | `web/src/pages/*` |
| 列表三种写法并存：`ProTable`（Market/Sops/Types）、`Table`（Lifecycle/McpGateways）、卡片网格（Dashboard） | 同上 |
| 筛选两种写法：`Segmented`（Tasks/Skills/Lifecycle）与 `Tabs`（McpGateways/Lifecycle） | 同上 |
| 侧栏配色在 `App.tsx` 里写死 6 个色值 | `App.tsx:142` |
| SOP 的「执行 → 记录 → 交付物」散在 Sops 页的两个抽屉里，没有独立的交付空间 | `pages/Sops.tsx` |

## 2. 菜单与目录

### 2.1 分组（属主 2026-11-01 定稿）

```
工作
  总览            /                日常入口：我的待办摘要 + 常用工作台 + 关键指标
  统一待办        /tasks
  驾驶舱          /cockpit         可自定义的数据看板
交付
  SOP 交付空间    /sops            SOP 列表 → 单个 SOP 的执行、记录、交付物（见 §4）
资源
  工作台市场      /market
  技能市场        /skills
治理
  生命周期全景    /lifecycle
管理（仅管理员可见，默认折叠）
  MCP 网关        /mcp-gateways
  类型管理        /types
  设置            /settings
```

- 一级菜单是**分组标题**，不可点；二级才是页面。分组最多 5 个，每组最多 6 项。
- 「管理」组只在持管理员口令时显示，不再和日常页并列。
- 每个页面一个专属图标，不复用；图标统一 antd `*Outlined`。
- 改名：「SOP 台」→「SOP 交付空间」，「工作台」→「工作台市场」，与页面标题一致。

### 2.2 目录（路由）规则

- 列表在 `/<资源>`，详情在 `/<资源>/:id`，子视图在 `/<资源>/:id/<视图>`，例如 `/sops/demo-rack-sop/runs/42`。
- 详情不再用抽屉承载完整内容；抽屉只用于**不离开列表的快速编辑**。详情要能分享链接、能刷新不丢。
- 面包屑 = 分组 / 页面 / 详情名，由 `PageContainer` 统一生成。

### 2.3 侧栏样式

侧栏用深色（与内容区浅色区分），新增 token：`nav-bg #0F172A`、`nav-text #CBD5E1`、`nav-text-active #FFFFFF`、`nav-item-active-bg #1E3A5F`，不再在 `App.tsx` 里写死。

## 3. 页面骨架（所有页面一致）

```
PageContainer
├─ 标题（typography.title）+ 一句说明（text-secondary）
├─ 右上：主操作（至多 1 个 primary）+ 次操作
├─ 筛选条（可选）
└─ 内容区：列表 / 看板 / 详情分区
```

- 所有页面都包 `PageContainer`，不允许裸 `Card` 当页面根。
- 页面内切换**视图**（同一批数据的不同切法）用 `Segmented`；切换**不同内容**用 `Tabs`。不再混用。
- 加载、空态、错误统一用 `Spin` / `Empty` / `Result`，空态必须给下一步操作（例如「发布第一个 SOP」）。

## 4. SOP 交付空间

一个 SOP 是一个「交付空间」，对应路由 `/sops/:slug`：

| 区块 | 内容 | 组件 |
|---|---|---|
| 头部 | 名称、版本、状态标签、负责人；主操作「开始执行」 | `PageContainer` 头部 + `StatusBadge` |
| 执行记录 | 每次 run 一行：编号、执行人、开始/完成时间、进度（步骤 x/y）、状态 | `ProTable`，点行进 `/sops/:slug/runs/:id` |
| 单次记录 | 步骤时间线 + 每步填写值 + 附件；无读授权时只显示元数据并提示（#309 已定的隐私契约） | `Steps`（纵向）+ `Descriptions` + 附件列表 |
| 交付物 | 本 SOP 所有 run 产出的附件与最终记录汇总，可按 run 过滤、下载 | `ProTable` |
| 定义 | 步骤与字段定义、版本历史 | `Tabs` 里的只读视图 |

- 列表页 `/sops` 只放 SOP 卡片或表格（名称、状态、最近执行、进行中 run 数），不再在抽屉里塞执行历史。
- 隐私：执行记录列表只给元数据；字段值和附件只在有读授权时出现，不靠前端隐藏。

## 5. 任务清单与列表

适用于统一待办、工作台市场、类型、MCP 会话等所有「一行一条」的页面。

- **一律 `ProTable`**（需要分页、搜索、列设置）；只有不足 10 行且不需要筛选的小表才用 `Table`。
- 列顺序：状态 → 标题/名称（可点） → 关键属性 → 负责人 → 时间 → 操作。
- 状态列用 `StatusBadge`，固定在最左；操作列固定在最右，最多 2 个直接操作，其余收进「更多」。
- 时间显示相对时间（「3 小时前」），悬停显示绝对时间；数字列右对齐 + `tabular-nums`。
- 统一待办的来源（market / ygl-trees / 生命周期）用 tag 标出，不靠颜色区分。
- 行密度用 antd `size="middle"`；批量操作出现在表头上方，选中后才显示。
- 筛选条：关键词搜索 + 最多 3 个常用筛选；更多筛选收进「高级筛选」。

## 6. 数据看板

适用于总览与驾驶舱。

- **栅格**：12 列，卡片宽度只取 3 / 4 / 6 / 12 列；卡片间距 `spacing.3`（12px）。
- **卡片四类**，每类固定结构：
  - 指标卡：`stat-label` 标签 + `display` 大数 + 环比（带方向，用 `success-text`/`danger-text`）；
  - 趋势卡：标题 + 折线/柱状图，图例在上；
  - 列表卡：标题 + 最多 5 行 + 「查看全部」链接到对应列表页；
  - 状态卡：工作台健康状态等，用 `StatusBadge` 网格。
- 卡片头：标题（`subtitle`）左，时间范围/操作右；卡片内不再嵌套卡片。
- 图表配色只用状态色与 `primary` 系，最多 5 个系列；超过就分组或改表格。
- 每张卡都要有空态和加载态；数据过期（超过刷新周期）时卡片头显示「数据截至 HH:mm」。
- 驾驶舱可拖拽布局沿用现有 react-grid-layout，但卡片宽度吸附到上面 4 档。

## 7. 自产台：菜单、焦点、状态持久化

自产台是他人写的独立页面，不走 antd。为了在门户里打开时观感和手感一致，每个自产台页面在 `<head>` 起始处带同一个**统一层**（`scripts/market-app-restyle/` 生成）：内联 `--wm-*` token + 基础排版 + 下面三条交互约定。台内逻辑不改，统一层只补语义和记忆。

### 7.1 菜单（页签 / 分段 / 锚点导航）

| 写法 | 判定 | 统一层做的事 |
|---|---|---|
| 一组可点项里**恰好一个**选中（`.on`/`.active`/`aria-selected=true`） | 页签 | 容器 `role=tablist`、项 `role=tab` + `aria-selected`；选中项 `tabindex=0`，其余 `-1`；←→↑↓/Home/End 切换并激活 |
| 台自己维护 `aria-pressed` | 切换按钮组 | 语义原样保留，只统一样式 |
| 一组链接都不选中 | 锚点导航 | 只统一样式，不加 tab 语义 |

- 选中态统一：`primary-subtle` 底 + `primary` 字 + 600 字重；项内计数/徽标继承选中色，不再各写一套。
- 深色只允许出现在导航条（顶栏/页头）：底 `nav-bg`，字 `nav-text` / `nav-text-active`。内容区一律浅色，不提供 `prefers-color-scheme: dark`。
- 台内链接一律同源相对路径（`/apps/…`、`/api/…`），不写死 `http://<内网 IP>:9800`——门户可能经任意入口访问。

### 7.2 焦点

- 键盘焦点统一 `:focus-visible` 2px `primary` 外框、偏移 2px；台内 `outline:none` 不得压掉它（统一层用 `!important`）。输入框聚焦时边框变 `primary`。
- 带 `onclick` 的非交互元素（`div`/`span`/`tr`…）自动补 `tabindex=0` + `role=button`（行用 `role=link`），回车/空格触发点击。新写的台请直接用 `<button>`/`<a>`。
- 尊重 `prefers-reduced-motion`：关闭动画与过渡。

### 7.3 状态持久化

按台命名空间存 `localStorage`（键 `wm:<slug>:<页面>:…`），刷新后恢复；读写全部 try/catch，存储不可用时页面照常工作：

| 记什么 | 何时写 | 何时恢复 |
|---|---|---|
| 当前页签 | 点击/键盘切换 | 加载后（含异步渲染完成后 4 秒内）；URL hash 已指定视图时让位于链接 |
| 搜索/筛选/排序控件（`type=search`、`select`，或 id/name/placeholder 含 search·filter·q·sort·搜索·筛选·排序） | `input`/`change` | 加载后回填并派发 `input`/`change`，让台内过滤逻辑重跑 |
| `<details>` 折叠区 | `toggle` | 加载后 |
| 滚动位置 | 滚动停 150ms（`sessionStorage`，只在本标签页） | 加载 400ms 后，URL 有 hash 时不恢复 |

- 只记**视图状态**，不记业务数据；业务数据走 `/api/apps/<slug>/data`。
- 台自己已有持久化（如 `frl_tab`、`pw.filter`）时两者并存：恢复前先判断当前是否已是目标状态，不重复触发。

### 7.4 菜单、目录、视图（应用外壳）

每个自产台都有同一套外壳（`wm-nav.js`，按台配置分组；台内 DOM 只加 class/id，不移动、不改逻辑）：

```
┌ 应用栏（吸顶 48px）：← 工作台市场 │ 台名 │ 菜单：分组1 分组2 … │ 视图：[分组|全部] ┐
├ 目录（左侧 220px，窄屏收进「目录」抽屉）┬ 内容 ───────────────────────────────────┤
│ 分组1                                   │ 页头（h1 与首个 h2 之前的内容，始终显示）│
│   区块 A  ← 滚动高亮                    │ 区块 A / 区块 B …                        │
└─────────────────────────────────────────┴──────────────────────────────────────────┘
```

| 部件 | 是什么 | 规则 |
|---|---|---|
| 菜单 | 台的业务分组（3～6 组），每组若干区块 | `role=tablist`，选中态 `primary-subtle` 底 + `primary` 字；←→/Home/End 切换 |
| 目录 | 全部分组及其区块的清单 | `<nav aria-label="目录">`；当前区块 `aria-current`，左边线 `primary`；非当前组的条目用 `text-secondary` |
| 视图 | 同一批区块的两种看法 | `role=radiogroup`：「分组」一次只显示一个菜单组（默认）；「全部」长页滚动，菜单随滚动跟随 |

- **区块** = 一个 `h2` 及其后的兄弟元素（到下一个 `h2` 为止）；按标题前缀归入分组，没配的归「其他」。
- **地址**：`#wm=<分组>/<区块id>`，「全部」视图加 `&v=all`。链接可分享，刷新不丢；没有 hash 时用本地记忆的分组和视图。
- 打印时隐藏外壳、展开全部区块。
- **只给业务看**（属主 2026-11-03）：自产台页面的读者是业务人员。验证器状态、spec 明细、运维台账、task list、表单自查记录、token/数据源/CORS/机器键之类的技术说明，属于工程和 agent 面，在页面上**整块不显示**，不进菜单和目录，不留隐藏入口。工程方经接口或 MCP 读取，数据与接口不受影响。业务也需要的段落（例如含税/未税口径图例）单独保留。分组表里用 `hideSections` / `hideNodes` / `keepNodes` 声明。
- 新台接入：在 `restyle.py` 的 `NAV` 里加一份分组表即可；已经统一过的台用「换层」只替换 `<head>` 里的统一层，正文不再转换。

## 8. 落地顺序（定稿后另开 issue）

1. 侧栏分组与改名、`nav-*` token（改动集中在 `App.tsx`，见效最快）。
2. 所有页面套 `PageContainer` 统一骨架。
3. SOP 交付空间拆成独立路由（列表 / 详情 / 单次记录 / 交付物）。
4. 列表统一到 `ProTable` 规则；统一待办先做。
5. 总览与驾驶舱按看板四类卡片重排。
